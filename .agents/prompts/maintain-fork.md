# 长期维护分支：上游同步 Prompt

将下面代码块完整复制到此仓库的新任务中。日常也可直接说：

> 按 `.agents/prompts/maintain-fork.md` 执行一轮上游同步，并更新 `docs/fork-maintenance.md`。

```text
请在当前 new-api 仓库执行一轮长期维护分支的上游同步。

先读 AGENTS.md、docs/fork-maintenance.md，以及实际涉及目录的项目规范。
维护文档是补丁清单和历史记录；分支、remote、SHA、工具版本、测试状态必须现场核验。
默认维护分支是 fix/anthropic-consume-log-cache-tokens，源是 origin/main，
fork 是 zhls-ayl/new-api。不得把当前分支的 tracking branch 当成官方上游。

本次授权：fetch、只读分析、必要的隔离 worktree / 恢复引用、merge、
保持既有功能所必需的最小冲突修复、相关测试、维护记录更新及 scoped local commit。
默认不 push、不创建或评论 Issue/PR、不发布、不部署、不启动生产服务。
仅当我明确要求推送时，核验目标后普通 fast-forward push 到 fork 的维护分支。
不要修改 Git 身份、remotes、已有 tracking 配置或改写共享历史。

执行要求：
1. 核对工作区、当前分支、所有 worktree、进行中的 Git 操作和两个 remote 的 URL。
   fetch 上游和 fork 后固定本轮目标 SHA，检查 fork 分支是否有本地未包含的提交。
   不覆盖、不自动 stash 无关修改；能安全隔离则隔离，必须用户选择时再提出具体问题。
2. 先查重。目标已包含且没有待处理补丁或验证事项时，报告无新增改动，不制造空 merge。
3. 根据补丁清单逐项核验行为。区分“历史有此 commit”和“当前代码仍有此功能”。
   对比本轮上游增量、维护分支相对目标的实际 tree diff，检查交叉改动和依赖链。
   上游已实现等价功能时，用代码和行为测试证明后移除重复实现，保留必要回归覆盖并更新清单。
   不能只凭标题、PR 状态、patch-id、文件无冲突或编译通过认定功能被保留或吸收。
4. 默认使用 merge，不 rebase / squash / reset 维护分支，不 force push。
   记录合并前 SHA 并建立本地恢复引用；使用固定目标 SHA 合并，提交前检查合并结果。
   禁止整文件使用 ours/theirs 解决业务冲突。保持本地补丁的业务契约，并纳入上游有效修复。
5. 优先使用 subAgents 并行做只读补丁审查及独立验证，保持单一 Git / 文件写入者。
   若要实际修改认证、数据库、计费、前端或插件实现，先执行对应项目规范和 skill 要求。
6. 按维护文档运行本地补丁回归、root 与 relaykit 独立检查及受影响前端检查。
   前端先 frozen-lockfile 安装、typecheck 和 build，补齐 web/dist 后再构建 root。
   数据库行为受影响时必须执行真实 SQLite/MySQL/PostgreSQL 验证；检查 SKIP，不能把退出码 0
   当成三数据库验证成功。缺少实例时如实记录阻塞，不能声明兼容性验证完成。
7. 测试失败先归因：合并回归、同环境上游失败、环境问题或疑似时序不稳定。
   首轮失败和复跑结果都保留；不得删测、放宽断言、无依据调大 timeout 或反复重跑到绿。
   发现稳定失败时，用固定上游 SHA 的隔离环境做最小对照；不顺手修复无关上游问题。
8. 明确区分 Git 已同步、补丁已验证、完整验证通过和可发布四种结论。
   已证明的合并回归必须解决后再提交。仅缺环境或有证据的上游问题时，可保存本地同步结果，
   但必须列出验证缺口，不能作为已验证版本交付；这种例外不覆盖更严格的当前项目规则。
9. 按 docs/fork-maintenance.md 更新补丁状态和同步日志：前后/目标 SHA、冲突处理、
   检查命令、工具及数据库版本、首轮/复跑结果、SKIP、证据位置、后续事项、推送状态。
   merge commit 后用独立 docs commit 记录其 SHA，避免自引用；所有提交只包含本任务文件。
   文档只记录截至提交时已知的推送状态，最终 push SHA 回执留在回复和持久证据中，下轮补记。
10. 最终复核目标是维护分支 HEAD 的祖先、本地补丁行为、剩余 tree diff、工作区状态。
    如已授权 push，额外核对 local HEAD、tracking ref 和远端实际 SHA 一致。

直接完成已授权步骤，不重复询问常规操作许可。只有凭现有证据无法决定、会丢失工作、
改变功能取舍或需要额外外部权限时才停下来说明具体分歧。
最终用中文简要报告同步提交、补丁状态、验证结论、未验证项及是否推送。
```
