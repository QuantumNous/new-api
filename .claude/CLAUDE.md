# 二次开发规范（随仓库共享，跨设备生效）

> 本文件是对官方 `CLAUDE.md` 的补充，会被 Claude 自动加载在官方规范之后。
> 它放在 `.claude/` 下并已纳入 git，所以其他设备 clone 后同样生效、变更也会被记录。
> 官方 `CLAUDE.md` 的所有规范（技术栈、JSON、数据库兼容、i18n、测试等）继续完全适用。

## 本仓库性质

这是 fork 自官方 `QuantumNous/new-api` 的二次开发仓库。目标：定制功能 + 持续跟进官方更新 + 自建镜像部署。

## 分支与工作流

- 所有二次开发都在 `custom` 分支进行；`main` 只用于同步官方，**不要在 main 上改代码**。
- 推送到 `custom` 会自动触发 `.github/workflows/build-ghcr.yml`，构建镜像到 `ghcr.io/amoresdk/new-api`。
- 同步官方更新一律用 **merge**，不要用 rebase。

## 核心原则：扩展而非修改（这是降低同步冲突的关键）

- 新功能优先放进**新文件 / 新模块**，尽量不改官方现有文件。
- 能用**配置 / 环境变量**实现的，不要改源代码。
- 必须改官方文件时，改动尽量**小而集中**。

## 绝对不要改动的官方文件（改了同步官方时必冲突）

- 官方的 `CLAUDE.md`、`.gitignore`
- 官方的 `.github/workflows/*`（自建构建已用独立文件 `build-ghcr.yml`，不要动官方那几个）

## 必须继续遵守的官方约束

- **品牌保护政策**：不得修改 / 删除 `new-api`、`QuantumNous` 的任何标识（名称、Logo、footer、镜像名、Go module path、版权等）。做功能定制可以，改名 / 换 Logo 会与此冲突。
- 官方 `CLAUDE.md` 的全部后端 / 前端技术规范依旧适用。

见本地文档 `claude_docs/new-api二次开发操作指南.md`（该手册目前是本地的、未进 git；如需在其他设备查阅，可另行纳入或自行拷贝）。
