# 产品判断原则

- 先保护 API 网关的核心承诺：可用、可控、可计费、可审计。
- 管理员能力与普通用户能力必须清晰分离，默认不扩大权限。
- 上游供应商差异应被明确表达；不为表面统一伪造能力或成功状态。
- 金额、余额、用量、模型和渠道状态属于高信息密度内容，优先准确和可解释。
- 新设置必须有明确用户、默认值、关闭路径和升级兼容策略。
- 新手流程应给出下一步，但不能自动创建付费资源、生产渠道或宽权限 key。
- 指标未知时标记 UNKNOWN，不用页面点击或 HTTP 200 代替真实端到端成功。

产品规格入口见 `docs/product-specs/index.md`。

## L1 发现结论：降低配置成本，但不取消身份恢复

### 期望结果

首个可观测结果是“普通用户从收到邀请到首次成功调用 API 的完成率提升”，而不是单纯减少表单字段。建议同时观察：首次 Key 保存/复制成功率、注册到首次调用耗时、Key 找回成功率、重置后旧会话拒绝率和邮件失败回滚率。当前基线与目标值均为 `UNKNOWN`，需要小范围实验后再设定。

### 机会—方案树

```text
结果：降低普通用户首次使用和凭据维护成本
├─ 注册字段过多
│  └─ 邮箱邀请 + 确认后自动创建账户和单主 Key
├─ 密码遗忘与支持成本高
│  └─ API Key 登录 + 邮箱一次性找回链接
└─ 多 Key 管理容易出错
   └─ 普通用户单主 Key；轮换代替删除/禁用；管理员和服务账号保留多 Key
```

### 高风险假设与最小实验

| 类别 | 假设 | 风险/确定性 | 最小实验与停止条件 |
| --- | --- | --- | --- |
| 可用性 | 用户能在一次性页面保存主 Key | 高/低 | 受控原型测试复制、关闭、重新登录；若保存失败率不可接受，保留密码/Passkey 作为首选恢复 |
| 安全 | 双用途 Key 的泄露风险可由一次性展示、轮换、撤销和限流控制 | 高/中 | 威胁建模+旧 Key/旧 Session 演练；任一路径可复用完整 Key 或绕过 step-up 即停止 |
| 可行性 | SMTP 故障不会留下半账户或无交付 Key | 高/低 | 注入发送失败、超时、重试；若无法证明原子回滚，不开启邀请注册 |
| 兼容性 | 管理员/服务账号多 Key 和密码用户不受影响 | 高/中 | 角色矩阵+并发数据库回归；任一角色权限扩大即停止 |
| 价值 | 邮箱找回比密码支持成本更低 | 中/低 | 小范围灰度比较找回成功率、工单率和首次调用完成率；无改善则不扩大模式 |

### 产品决策

推荐“双轨认证”：普通用户可用单主 Key 登录和调用，密码/Passkey/2FA 保留为兼容或 step-up；默认不推荐把完整 Key 放入邮件，也不推荐用多个旧开关拼接出半启用模式。当前 L1 已在生产完成邀请、注册、Key 登录、轮换、找回和缓存人工验证；邮件发送完整 Key 属于产品方明确接受的部署例外，仍需保留风险记录。

### 复审收口（2026-08-13）

- “邮件邀请”已作为默认产品承诺：`SinglePrimaryAPIKeyEnabled` 开启后强制 `invite_token`，并阻断普通注册、OAuth 新用户和微信新用户的公开建户旁路。公开邮箱 OTP 注册如需保留，应另行设计迁移兼容模式。管理员用户页已提供邀请入口，后端仍是最终权限边界。
- 注册完成返回一次性 `full_key`，不自动建立后台 Session；用户保存后重新登录。这样更符合“重置/创建后保存，再登录”的产品意图，也避免把邮件交付、数据库事务和会话创建耦合成不可恢复状态。
- 主动或找回轮换提交后，缓存发布/旧 Session 撤销失败现在返回一次性新 Key并附非敏感告警，同时继续尝试两步；旧 Key和旧 AuthVersion 仍在事务内失效。
- 跨库运行时、真实 SMTP 投递和浏览器 E2E 尚未验证；MySQL 邮箱锁的 gap-lock 前提及 SQLite busy 行为列为发布前专项检查。

## 单主 API Key 模式的产品边界（L1）

推荐采用“邮箱身份 + 单主 Key + 密码兼容”的双轨方案。普通用户只保留一条主 Key，主 Key 可调用 API 和登录后台；管理员、服务账号继续使用多 Key。简化注册只能作为完整模式开放，必须同时具备邮箱确认、原子轮换、旧会话撤销、找回链接一次性消费、限流和审计。

默认初始邮件只发送一次性邀请链接，完整 Key 在 HTTPS 页面一次性展示；本次 L1 生产部署按产品方要求额外把注册后完整 Key 发送到受邀邮箱，作为明确的风险接受例外。邮箱找回请求必须统一响应，不能枚举账户；只有用户点击一次性、短时有效链接后才轮换 Key。

产品指标建议先观察：注册到首次 API 调用完成率、首次 Key 保存/复制成功率、Key 找回成功率、重置后旧会话拒绝率和邮件失败回滚率。没有这些运行证据时，状态只能是 DRAFT/L1，不得宣称“闭环完成”。
