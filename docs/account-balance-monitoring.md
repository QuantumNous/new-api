# 上游账户余额查询

渠道的兼容账单接口可能返回 API Key 限额。无限额度 Key 的 `100000000` 占位值不能作为账户钱包余额；遇到该值时查询会报错，不再计算并写入假余额。

## 配置入口

管理员进入「渠道」→ 对应渠道的菜单 →「查询余额」→「账户余额设置」。需要 `channel.sensitive_write` 权限。

1. 开启「查询上游账户钱包」。
2. 填写上游账户站点，例如 `https://goeasyapi.xyz`，不要填写 `/wallet` 或 `/api/user/self`。
3. 填写上游用户 ID（数字）。

   GoEasyAPI 已实测要求此字段：2026-09-07，仅携带账户访问令牌调用 `/api/user/self` 返回 HTTP 401，提示 `Unauthorized, New-Api-User header not provided`。如果个人资料不显示编号，可在 Chrome 开发者工具的 Network 中查看该站账户请求的 `New-Api-User` 请求头；不要把本站渠道 ID 当作上游用户 ID。

4. 填写上游「个人资料 → 访问令牌」中的账户令牌。这是独立凭据，不会替换模型调用 Key，也不会作为模型请求头发送。
5. 保存后点击「更新余额」，与上游钱包核对。

保存配置会清除旧查询结果并显示「尚未查询」。令牌只保存在服务端，不会由配置或渠道查询接口返回。留空表示保留已保存令牌；更换站点或用户 ID 必须重新填写令牌。关闭此功能并保存会删除其凭据。

## 取数与币种

- `GET {账户站点}/api/status`：读取 `quota_per_unit`、`quota_display_type` 和 `usd_exchange_rate`，不携带凭据。
- `GET {账户站点}/api/user/self`：携带 `Authorization: Bearer <账户令牌>` 和 `New-Api-User: <用户ID>`，读取账户 `data.quota` 并核对 `data.id`。
- USD 钱包：余额 = `quota / quota_per_unit`。
- CNY 钱包：余额 = `quota / quota_per_unit * usd_exchange_rate`。
- 金额与 `balance_currency` 一起保存，前端直接显示上游币种，不再套用本站汇率。空 `balance_currency` 保留旧渠道的 USD 显示规则。

当前支持上述 New API 账户接口的 USD/CNY 钱包。其它站点、币种或不兼容响应会明确报错。查询使用 HTTPS、15 秒总超时、256 KiB 响应上限，不跟随重定向。HTTP/JSON/配额/账户校验失败均不会覆盖上次成功的余额和时间。

## 自动刷新

现有 `CHANNEL_UPDATE_FREQUENCY` 环境变量仍控制刷新间隔，单位为分钟。已启用的渠道会使用已保存的账户配置查询；多密钥渠道也可以显式绑定一个账户钱包。一个多密钥渠道若混用了多个账户，该配置只代表填写的账户。

账户余额刷新只监测余额，不根据零余额自动禁用渠道。未配置账户查询的旧渠道保持原有自动禁用行为。同一上游账户绑定多个渠道时会分别查询，不能把这些渠道余额相加当成账户资金总额。

## 部署与验证

需要同步更新前后端。启动时由现有 GORM 迁移增加 `channels.balance_config`（服务端配置）与 `channels.balance_currency`（上游币种）两列。部署前备份数据库；回退二进制前应清除账户查询结果，避免旧前端把原币种余额当作 USD 再换算。

自动化测试覆盖配额换算、无限限额拒绝、零余额、错误响应不覆盖余额、凭据不返回、替换站点需新凭据、配置变更后拒绝旧结果、权限路由和表单保存行为。真实上游联调还需要有效的账户令牌与用户 ID。

2026-09-07 已完成本地隔离实例与 GoEasyAPI 的真实联调：从页面保存独立账户配置后查询成功，弹窗及渠道列表均以 CNY 显示，按两位小数展示的结果与上游钱包一致。此次验证未更新生产站点。
