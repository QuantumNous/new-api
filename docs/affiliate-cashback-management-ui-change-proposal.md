# 邀请返现管理页面修改方案

## 1. 目标

将当前“转入余额 + 空状态转入记录”改成以“被邀请者充值记录”为核心的管理页面。用户可以按时间查看每笔被邀请者充值产生的返现，并在同一行完成余额转入操作。

设计稿：`docs/affiliate-cashback-management-ui-v2.svg`

## 2. 页面结构

1. 顶部统计保留四项：已冻结返现、可转入、已转入、累计获得。
2. 不再拆分“被邀请者充值记录”和“转入记录”；转入状态直接在同一条记录中展示。
3. 记录区按 `recharge_time DESC, id DESC` 排序，默认展示最新充值。
4. 记录区右上角提供邮箱/充值时间模糊搜索、排序选择，分页加载，避免一次加载全部历史记录。
5. 每一行展示：
   - 被邀请者隐私保护邮箱
   - 充值时间
   - 充值额度
   - 返现方式（比例或固定）
   - 当前可返现余额
   - 解冻时间
   - 转入账户余额操作
   - 转入状态（冻结中、可转入、已转入）

## 3. 操作状态

### 冻结中

- 操作按钮保持禁用态，避免误操作。
- 按钮主文案保留“转入账户余额”，下方使用小字显示“还有 X 天解冻”。
- 解冻时间同时在“解冻时间”列展示完整日期。
- `X` 按自然日计算，至少显示 `还有 1 天解冻`；当天解冻显示“今天解冻”。

### 可转入

- 操作按钮使用主色，文案为“转入账户余额”。
- 点击后弹出确认框，显示本次转入金额、转入后的账户余额和不可撤销提示。
- 请求成功后刷新当前行和顶部统计；转入时间保存在当前记录的详情中。

### 已转入

- 操作按钮置灰，文案改为“已转入余额”。
- 不再允许重复转入；通过当前记录详情查看转入时间、金额和请求编号。

## 4. 数据与接口调整

### 查询接口

复用 `/api/affiliate/invitee-topups`，补充或确认以下参数：

- `page`
- `page_size`
- `keyword`: 邮箱片段或充值时间片段，服务端模糊匹配
- `status`: `all`、`frozen`、`available`、`transferred`
- `sort`: `recharge_time_desc`（默认）或 `recharge_time_asc`

返回项至少包含：

- `masked_invitee_email`
- `invited_at`
- `recharge_at`
- `recharge_amount_cny`
- `reward_mode`
- `reward_rate_percent` 或 `fixed_reward_cny`
- `available_reward_cny`
- `unfreeze_at`
- `transfer_status`
- `transferred_at`

接口只返回已经脱敏的邮箱。脱敏规则建议保留首字符和域名，例如 `a***@example.com`，不能由前端自行处理原始邮箱。

搜索框占位文案为“搜索邮箱或充值时间”，支持输入完整邮箱、邮箱片段，以及日期时间前缀（`YYYY`、`YYYY-MM`、`YYYY-MM-DD`、`YYYY-MM-DD HH:mm`、`YYYY-MM-DD HH:mm:ss`）。前端输入后防抖约 300ms 请求，清空搜索时恢复全部记录并回到第 1 页。邮箱搜索由服务端在权限范围内匹配原始邮箱，响应仍只返回脱敏邮箱，避免前端接触完整邮箱。

### 转入接口

复用 `POST /api/affiliate/balance-transfers`，请求从“按总额转入”调整为支持单笔记录转入：

```json
{
  "reward_id": 123
}
```

服务端必须再次校验：返现状态为可转入、冻结时间已到、记录未转入、用户归属正确。重复请求返回幂等成功或明确的“已转入”状态，不能重复增加用户 quota。

## 5. 前端修改范围

- `web/default/src/features/wallet/components/dialogs/affiliate-center-dialog.tsx`
  - 移除充值记录和转入记录双 Tab，保留单一充值记录列表。
  - 将记录渲染从空状态/简单表格改为可分页数据表。
  - 增加状态标签、解冻倒计时文案和三种转入按钮状态。
  - 增加邮箱/充值时间快捷搜索框，展示加载和清空状态。
- `web/default/src/features/wallet/hooks/use-affiliate.ts`
  - 增加 `keyword`、`status`、`sort` 查询参数，搜索变化时重置分页。
  - 转入成功后同时刷新 summary、invitee-topups、balance-transfers。
- `web/default/src/features/wallet/api.ts`
  - 扩展充值记录类型和单笔转入请求类型。
- `web/default/src/features/wallet/types.ts`
  - 增加脱敏邮箱、返现方式、解冻时间和转入状态字段。
- `web/default/src/i18n/locales/*.json`
  - 补充冻结、解冻、可转入、已转入、隐私保护和确认弹窗文案。

## 6. 交互与隐私约束

- 充值额度和返现金额展示 CNY，返现比例统一带 `%` 符号。
- 仅展示脱敏邮箱，不展示受邀者完整邮箱、用户 ID 或付款订单号。
- 记录默认按充值时间倒序，时间格式统一为 `YYYY-MM-DD HH:mm`。
- 加载、空状态、错误、转入中和转入成功都需要明确反馈。
- 移动端将表格改为纵向记录卡片，操作按钮保持在卡片底部且不被截断。

## 7. 验收标准

- 页面首次打开直接展示最新充值记录，不再进入空的“转入记录”页面。
- 每条记录都能看见脱敏邮箱、充值额度、返现方式、可返现余额和解冻时间。
- 冻结记录按钮不可点击，并显示“还有 X 天解冻”。
- 可转入记录点击一次只增加一次用户 quota，成功后按钮变为灰色“已转入余额”。
- 已转入记录刷新页面后仍保持灰色，不会重复转入。
- 状态筛选、时间排序、分页和顶部统计与接口返回一致。
