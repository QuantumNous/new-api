# 代理客户管理与 gpt-image-2 降价

状态：本地实现，尚未发布。分支：`codex/agent-customer-pricing`。

## 确定的业务规则

- 不增加代理分账、供货价、利润或返佣计算；已有普通邀请奖励逻辑保持原状。
- 站长在“用户 → 操作菜单 → 代理权限”开通或停用代理，不提升该账号的 User.Role。
- 开通后纳入全部已有及未来直接邀请客户，复用服务端保存的 `users.inviter_id`，不包括下级客户的客户。
- 代理仅能调整自己名下客户的 `gpt-image-2` 单价，默认 6 分，允许 2–6 分人民币/张。
- 同一代理名下客户使用统一价格，其他模型继续采用原有平台规则。未归属有效代理的客户也采用原有平台规则。
- 代理停用或其账号被禁用后，新请求回到原平台计价；已提交批次保留原锁定代理价格。

## 界面

“代理中心”包含专属注册链接、客户数、充值客户数、累计充值、客户名单、个人充值明细及单价设置。
只有开通的代理显示该入口；直接访问接口仍会在后端校验权限。
充值仅统计现有 TopUp 成功订单的 Money 字段，排除待支付订单和余额内部支付。不根据余额、赠送额度或使用量推算充值。
Epay 按 CNY、Stripe/Creem 按 USD 分别展示；未知支付来源单独保留来源标签，不混入人民币总额。退款以原支付系统更新后的订单状态为准，本次不新增退款账务系统。
客户在 AI 绘图页和模型广场看到自己的代理价格，图片结果区保持小图和下载布局。

## 实现

- `model/agent.go`：代理权限、单价、审计记录、直接客户与成功订单查询。
- `controller/agent.go`：登录态代理接口、站长管理接口、客户本人有效价格。
- `service/agent_price.go`：服务端定价与人民币到现有 quota 的换算。
- `relay/helper/price.go` / `service/text_quota.go`：预扣与结算使用同一个代理报价，金额不再次乘分组或充值倍率。
- `web/src/features/agents/`：代理中心及用户管理中的授权弹窗。

新增表：`agent_profiles`、`agent_price_changes`。
批次新增 `agent_quote_locked`、`agent_quote_json` 保存内部报价，不暴露为可写请求参数。
开通、停用、调价记录操作人、前后值、时间和版本。并发更新要求匹配版本，防止旧页面覆盖新设置。

代理接口位于 `/api/agent`，只能根据认证账号操作本人数据。`/api/agents/:id` 只允许 RootAuth 站长访问。
客户只获得自己 gpt-image-2 的有效价格信息，代理不会获得客户密码、API Key、提示词或图片访问权限。

## 锁价与兼容

代理价适用于网页登录的图片生成/编辑，以及客户 API Key 调用的 OpenAI Images API；其他协议调用 gpt-image-2 时会提示使用 Images API，避免把未知图片数量按文字请求计费。
按请求的图片数量计算费用。网页批量仍是一张一个请求。
批次创建时将代理、价格版本、人民币分值、单张 quota 固定下来，之后代理改价不会影响该批任务。
网页提交携带展示价格版本；如果已变化，拒绝新建并刷新价格，等待客户重新提交。
同一提交标识重试会返回原批次，即使期间价格变化也不会重建；价格版本提示不参与创作内容去重。
失败预扣退款沿用原账务逻辑，使用原预扣额，不重新查询最新价。原系统退款为异步执行。
旧版遗留批次在启动时标记为无代理报价，避免升级后启用代理改变这些旧任务的计价来源。

## 验证

本地 HTTP 模拟上游验证了：
- 8 张按 0.03 元提交，代理改成 0.02 元后仍按总计 0.24 元结算。
- 后续 API 请求按 0.02 元执行；伪造 price、agent_id 无效。
- 请求失败期间价格变为 0.05 元，退款仍退原来预扣的 0.02 元。
- 同一批次跨价格变化的重复提交仍返回原批次。
- 分组倍率不与最终代理价叠加，客户展示价与扣费规则一致。
- 原普通账号角色不变；代理不能调用站长接口、修改其他代理或查看非本人客户的充值。
- 历史直接邀请客户纳入；间接客户、待支付订单不计入。

Chrome 使用明确的本地示例数据检查了代理中心、改价保存、客户充值明细及用户管理中的代理授权入口。
未修改生产站点或真实用户权限，未调用收费模型。
