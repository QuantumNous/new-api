# AI 绘图批量生成与提示词模板

开发基线：`2f07c0700434c243b08847d7a1ed03fb5cc80989`。
分支：`codex/batch-ai-drawing`。当前为本地开发版本，尚未部署线上。

## 使用流程

1. 选择内置“电商商品图”模板，或客户自己保存的模板，内容会填入提示词输入框。
2. 补充本次商品名称、卖点、参数、画面要求。已有需求不会因选用模板而直接丢失。
3. 选择比例和数量后生成。数量留空默认 1 张。

“存为模板”把当前提示词另存到客户账号；铅笔按钮编辑已选模板。编辑内置模板会保存为客户自己的副本。
修改主输入框只影响本次生成，不会自动覆盖已保存的模板。
模板保存在服务端数据库，可在刷新页面或换设备登录后继续使用；每人最多 20 个，支持修改和删除。
模板不调用文字模型、不产生拆分费用；此前的 AI 规划入口、接口和文字模型配置已移除。
模板解决重复输入，不会自动将整套需求拆成不同的逐张提示词。普通批量会将同一最终提示词分别发送给生图模型。

## 界面与生图

保留原双栏布局、卡片和按钮风格。右侧只排列图片和下载按钮，顶部保留打包下载；桌面缩略图宽 144px，手机使用两列。
不显示图片标题、像素尺寸、到期时间、进度或批次选择。
提供 1:1、3:4、16:9、4:3、9:16、2:3、3:2、21:9；每批默认最多 20 张，管理员可调整至 100。
同一批次按固定编号排列。失败图保留位置但下载不可用；ZIP 只包含尚未过期的成功图片。

服务端队列默认全站并发 4，每用户、每渠道最多 2。关闭网页不取消队列。
提交标识按用户去重，异常上游请求不会自动重发；接口保留单图重试、结果取回能力，取回已有响应不再次调用生图。
计费、用户权限、分组、渠道选择及限流复用现有 New API 链路。

## 保存与清理

图片完成后保留两小时，到期立即禁止访问，服务运行时每分钟清理一次。图片取回不延长原到期时间。
生成新批次不提前删除仍有效的旧文件；简化结果区显示本次提交或最新批次。
模板属于长期账号数据，不受图片过期清理影响；修改和删除只能由模板所属用户操作。

Docker 默认 `DRAWING_STORAGE_DIR=/data/drawing-temporary`，必须位于持久化卷内，不能暴露为公开静态目录。
非 Docker 默认使用工作目录下 `data/drawing-temporary`。多实例必须共享同一存储卷。
图片与响应临时文件应排除在长期备份、CDN 持久缓存之外；模板保留在正常数据库备份中。
旧版 IndexedDB 的无期限图片缓存，在新版页面首次访问时清除；被旧标签页阻塞时提示关闭旧标签页。
已经下载到客户设备的图片、关闭浏览器中的旧缓存和上游副本，无法由服务端远程销毁。

## 实现和配置

- `model/drawing_batch.go`：持久化批次、逐张状态和并发领取。
- `controller/drawing_worker.go`：后台执行，重建用户上下文并调用现有 Relay。
- `service/drawing_storage.go`：私有文件存储、过期清理、尺寸和文件类型检查。
- `model/drawing_template.go`、`controller/drawing_template.go`：个人提示词模板 CRUD 和账号隔离。
- `web/src/features/ai-drawing/components/prompt-templates.tsx`：模板选择、填入、编辑、保存。

登录后的 `/pg/drawing/templates` 提供列表和创建，`/pg/drawing/templates/:id` 提供修改、删除。
模板名称最多 80 字，内容最多 16000 字节；生成图片文件最多 32 MiB，ZIP 原图总大小最多 256 MiB。

系统设置中只需配置 `DrawingBatchMaxCount`（默认 20）和 `DrawingBatchConcurrency`（默认 4），不需要额外文字模型。
首次启动创建 `drawing_batches`、`drawing_items`、`drawing_queue_locks`、`drawing_templates` 四张表。

批量执行参考 [KDB-Wind/gpt-image-2-studio](https://github.com/KDB-Wind/gpt-image-2-studio/tree/3695b45c3c8425e6fa95c07453a4ae7c288fb81e) 的独立任务、共享参考图和有限并发思路，沿用本仓库的界面和后端。

## 验证与上线边界

本地模拟上游覆盖 8 张图生图、16 张文生图、独立计费、失败预扣返还、上游异常不自动重发、图片取回不重复扣费。
已验证账号隔离、模板创建/修改/删除、保存上限、内容校验及图片清理不会删除模板；controller 和 model 包完整测试通过。
前端组件测试验证模板填入保留本次需求、临时修改不覆盖模板、按名称保存；Chrome 检查模板选择、编辑、保存和刷新后选用。

service 包原有两项缓存测试失败已在未修改基线复现：
- `TestObserveChannelAffinityUsageCacheByRelayFormat_MixedMode`（期望 2，实际 3）。
- `TestObserveChannelAffinityUsageCacheByRelayFormat_UnsupportedModeKeepsEmpty`（期望 1，实际 4）。
不能把完整 service 回归报告为通过。

未调用线上付费模型，实际渠道的八种比例支持、出图质量和商品一致性仍需实测。
上线前还需核对实际主机/容器版本、数据库恢复点、持久卷和临时图片备份排除项；本地实现不会自动改动线上部署。
