把 AI 浏览器测试迁移到其他项目

本文把“录制核心流程、严格语义回放、AI 有边界发散、候选三次独立验证、脱敏 artifact、GitHub Draft PR、人工合并进回归套件”的浏览器 QA 方案抽象成项目无关模板。它不绑定任何特定业务域名，目标是让 Web 项目能在 CI/CD 或独立调度中运行可审计、可清理、可控预算、不会自动 merge 的 AI 浏览器测试。

1. 适用场景与非目标

适用场景 需要验证真实浏览器流程、邮件或第三方回调、前端异常、关键路径回归、发布前只告警门禁的项目。
迁移目标 把个人电脑录制的流程变成云端或 Runner 中可重复运行的测试，并保留证据、清理和成本边界。
不适合 纯 API 单元测试、确定性 DOM 断言已足够的流程、需要绕过 CAPTCHA 或真实支付的流程。
非目标 不自动批准发布，不访问生产写路径，不保存真实凭据，不把 AI 探索结果直接当作产品结论。
迁移原则：先让 replay 严格稳定，再增加 AI 发散。核心流程失败时，只做诊断和证据采集，不进入广泛探索。

2. 迁移决策表

决策点推荐默认值何时调整风险
运行位置 容器化执行器 + 私有 broker + 独立 cleanup 小项目可先用 self-hosted runner；强隔离项目用云 Job 或 Kubernetes Job。 直接在 CI runner 放所有凭据会扩大泄露面。
回放方式 语义 replay：按目标状态、可访问名称、URL、文本意图定位 非常稳定的控件可补充 selector，但不能只依赖坐标。 坐标回放对布局、语言、缩放和动画非常脆弱。
AI 探索 核心 checkpoint 之后开启，限制时间和 action 数 需要高置信发布门禁时，先把探索发现转成确定性测试。 无边界探索会制造费用、误报和数据访问风险。
结果处理 先只告警，报告私有存储，摘要脱敏 replay 连续稳定后，可把 replay_failed 作为阻断条件。 直接阻断发布会把基础设施波动变成交付风险。
IaC 独立 state/root，两阶段 bootstrap 已有平台模块成熟时，可复用模块但保持状态隔离。 与生产 root 混用 state 会让 drift 和 QA 资源互相牵连。

3. 目标架构

通用方案由六个边界清晰的组件组成：调度器只负责构建、部署和启动；执行器拥有浏览器与模型进程；broker 持有第三方敏感凭据；evidence 管道负责截图、日志和脱敏；cleanup 独立兜底；provider adapters 隔离云厂商差异。

边界职责禁止
调度器选择 mode、构建镜像、注入非敏感变量、等待 main/cleanup 真实结束。不持有 OAuth refresh token，不解析邮件正文，不写测试业务逻辑。
执行器启动浏览器、模型、MCP、预算控制、结果 schema 校验和 artifact 上传。不读取 broker 的 OAuth payload，不接受任意模型或任意 URL 输入。
Broker最小化暴露验证码、回调或外部系统查询能力。不返回完整邮件、header、refresh token 或任意账号查询结果。
Evidence截图遮罩、console/network 投影、路径白名单、上传前脱敏。不上传原始 Playwright output、Cookie、Authorization、完整 API key。
Cleanup用同一 run identity 重新登录并幂等删除测试工件。不依赖模型最后一句话，不把 cleanup 成功交给 AI 判断。

1. record录制关键业务路径，写成业务意图、断言、允许 origin 和 cleanup 契约。

8. Draft PRGitHub bot 按 fingerprint upsert Draft PR；不自动 approve 或 merge。
9. human merge人工审核后合并，enabled fixed case 才进入 regression suite。

3.1 Portable UI / Network Assertion DSL：参考项目已验收，迁移项目需重跑

迁移到别的产品时，可以把这组 DSL 当作可移植能力清单。Flatkey staging 已用一个非变更型 coverage candidate 验证 UI 断言和网络否定断言的 runtime/聚合路径；但每个新项目仍必须用自己的 staging origin、自己的 allowlist 和自己的 cleanup 语义重新跑三次 attempt，不能直接继承参考项目的验收结论。
能力迁移说明
begin_network_capture步骤能力；空对象；网络断言必须在同一 case 中有且只有一次 capture，并且只看 capture 之后的浏览器请求。
element_visibleUI 状态断言，使用 role / label / text / test_id 等语义 locator。
element_hiddenUI 状态断言，使用语义 locator。
element_enabledUI 状态断言，使用语义 locator。
element_disabledUI 状态断言，适合证明不可提交、不可继续、不可危险操作。
element_value_equalsUI 值断言，只保留 locator 和 value。
element_count_equalsUI 数量断言，只保留 locator 和 count，count 范围 0..1000。
network_request_sent网络断言，只保留 same-origin request 的 method、origin、pathname 和 timeout。
network_request_not_sent网络断言，只保留 same-origin request 的 method、origin、pathname 和 timeout。

网络监听是显式边界，不是通用抓包能力。候选只能表达 method / origin / pathname / timeout；同源以当前 fixed case 的 staging origin 为准。query、fragment、header、body、cookie、Authorization、auth credential、OAuth token、webhook secret 和任意请求 payload 都不能进入 proposed_case、candidate bundle、artifact、PR 或摘要。

# 安全示例：空名称不点击提交，只断言按钮不可用
{
  "steps": [{"navigate": {"path": "/settings/keys/new"}}],
  "assertions": [
    {"element_disabled": {"locator": {"by": "test_id", "test_id": "submit"}}}
  ]
}

# 安全示例：弹窗打开前开始 capture，再证明没有提前创建
{
  "steps": [
    {"navigate": {"path": "/settings/keys"}},
    {"begin_network_capture": {}},
    {"click": {"locator": {"by": "role", "role": "button", "name": "New key"}}}
  ],
  "assertions": [
    {"element_visible": {"locator": {"by": "role", "role": "dialog", "name": "Create key"}}},
    {"network_request_not_sent": {"method": "POST", "path": "/api/keys", "timeout_ms": 0}}
  ]
}

这组 DSL 不改变 candidate 三次验证和 PR 流程：finding / coverage candidate 仍先生成 sanitized bundle，再跑三个独立 attempt，3/3 聚合后才进入 Draft PR；Draft PR 仍需要人工 review 和 merge，合并后 fixed case 才进入 regression suite。

4. Record 格式与 Replay Contract

录制产物不是浏览器操作流水账，而是可迁移的业务意图记录。record 应描述“用户要达到什么状态”和“允许怎样恢复”，replay contract 应定义成功、失败、证据和停止条件。

推荐 Record Schema

{
  "schema_version": 1,
  "flow_id": "new-user-onboarding",
  "target_app": "APP_NAME",
  "allowed_origins": ["https://APP_STAGING_ORIGIN", "https://APP_DOCS_ORIGIN"],
  "identity_inputs": ["username", "email_alias", "password"],
  "steps": [
    {
      "id": "open-signup",
      "intent": "从公开站点进入注册页",
      "start_url": "https://APP_STAGING_ORIGIN",
      "success": [
        "URL 匹配 /signup 或注册表单可见",
        "注册按钮或标题可通过可访问名称识别"
      ],
      "selectors_hint": ["role=link[name*=注册]", "role=button[name*=Sign up]"],
      "recovery": ["刷新一次", "回到 start_url 后重新寻找 CTA"]
    }
  ],
  "checkpoint": {
    "id": "core-replay-complete",
    "must_prove": ["账号已登录", "关键资源已创建", "可清理身份已记录"]
  }
}

字段名可以按团队规范调整，但必须保留：版本、允许 origin、身份输入、步骤意图、成功断言、恢复策略和 checkpoint。

Replay Contract

契约项要求
定位优先使用 role、label、文本意图、URL 状态和业务断言；selector 仅作 hint。
恢复允许有限刷新、返回上一步、重新寻找同义按钮；禁止创建第二个测试账号来掩盖失败。
checkpoint只有核心状态可证明且 cleanup 有足够身份信息时，才能进入探索。
输出固定 JSON schema：replay、exploration、budgets、findings、coverage_candidates；额外字段 fail closed。findings 和 coverage_candidates 的每个元素都必须包含 nullable proposed_case。
失败分类cleanup_failed 优先级最高，其次 infrastructure_failed、replay_failed、findings_detected、passed。

5. 如何把录制 Skill 去项目化

迁移时不要直接复制包含真实业务名、真实域名和个人录制痕迹的 Skill。先拆成四层：通用动作、项目配置、环境策略和敏感 broker。

  1. 抽象输入：把邮箱、用户名、密码、起始 URL、语言和 expected credit 等值改为 runtime 注入。
  2. 替换绝对事实：把“点击某产品名按钮”改成“点击进入目标工作区的主 CTA”，把真实域名改成 APP_STAGING_ORIGIN。
  3. 保留业务断言：保留“账号完成注册”“API key 可见但不复制完整 secret”“文档入口可达”等可证明结果。
  4. 移除人工接管：录制给真人的提示要改成 runtime policy，例如“本次测试已授权使用一次性身份完成注册”。
  5. 禁止模型自由扩权：Skill 只描述业务流程，不暴露 secret 名称、broker URL、云项目、bucket 或 runner 路径。
# skills/new-user-onboarding/SKILL.md
---
name: new-user-onboarding
description: Replay the staging new-user onboarding flow with runtime-provided identity.
---

Use only:
- APP_STAGING_ORIGIN
- TEST_USERNAME
- TEST_EMAIL
- TEST_PASSWORD
- get_current_verification_code
- qa_capture_screenshot

Stop at checkpoint only after:
- the account is logged in;
- the onboarding landing page is usable;
- the test-created resource can be enumerated by cleanup;
- no production origin was visited.
去项目化结果：Skill 仍保留流程语义，但把项目差异移到配置和 adapters。复制到新项目时，只需要替换配置、broker 查询逻辑和 cleanup API。

6. 执行器、Broker、Evidence、Cleanup 与 Provider Adapters

执行器

  • 启动一个 supervisor-owned 浏览器，Playwright MCP 只通过 CDP attach，不让模型启动第二个浏览器。
  • 为 Codex 或其他模型进程使用临时 home、临时 workspace、固定模型配置和固定 schema。
  • 通过 allowlist proxy 限制 origin、阻断 metadata、内网、生产域名和非 HTTP(S) scheme。
  • 将 replay 和 exploration 的预算写入 runtime state，由 MCP wrapper 在每次 tool call 前检查。

MCP 审批与工具白名单模板

迁移到其他项目时，非交互执行器应保持全局 approval_policy = "never"，再对少量项目专用 MCP server 写 default_tools_approval_mode = "approve" 和精确 enabled_tools。这不是放开审批，而是把可用工具收敛到可审计白名单；禁止 wildcard、yolo、danger-full-access、任意 shell、任意文件读取或任意网络工具。

approval_policy = "never"

[mcp_servers.browser]
required = true
default_tools_approval_mode = "approve"
enabled_tools = [
  "browser_navigate",
  "browser_click",
  "browser_type",
  "browser_snapshot",
  "browser_console_messages",
  "browser_network_requests",
  "read_docs"
]

[mcp_servers.evidence]
required = true
default_tools_approval_mode = "approve"
enabled_tools = ["capture_screenshot"]

[mcp_servers.broker]
required = true
default_tools_approval_mode = "approve"
enabled_tools = ["get_current_verification_code"]

[mcp_servers.control]
required = true
default_tools_approval_mode = "approve"
enabled_tools = ["replay_checkpoint", "start_exploration"]
检查项迁移要求
浏览器 MCP只能连接执行器已启动的浏览器；不允许模型启动第二个浏览器或绕过 proxy。
Evidence MCP工具参数只允许逻辑名；不接受路径、selector、raw screenshot 或关闭遮罩选项。
Broker MCP调用输入由 runtime 绑定当前 run；不允许模型传任意邮箱、alias、OAuth scope 或第三方账号。
Control MCPcore 模式只回放到 checkpoint 并停止；只有 normal 模式才能在 checkpoint 后进入有预算探索。
模板中的工具名是项目占位符。落地时必须把每个工具名替换为你的 MCP 实际导出名称，并用测试证明没有 *、隐式工具组或危险执行权限。

Broker

broker 是敏感系统的最小代理。它可以查邮件验证码、读取一次性回调状态或交换 OAuth code，但只能返回当前 run 需要的最小字段。

POST /v1/current-code
Content-Type: application/json

{
  "run_id": "GITHUB_RUN_ID",
  "email_tag": "qa-RUN_ID-8CHARHMAC",
  "start_time": 123456789
}

如果目标系统也有邮箱长度校验，先把完整 plus alias 算清楚。Flatkey staging 后端的完整邮箱上限是 50 字符，因此示例使用短前缀和 8 位 HMAC 后缀，而不是更长的项目名前缀。

broker 必须验证 run id、alias/tag 格式、时间窗口、调用身份和请求大小。错误只返回枚举码，例如 pending、invalid_time_window、oauth_invalid_grant。

Evidence

  • 截图由受限工具触发，工具只接收逻辑名，不接收路径、selector 或关闭遮罩的参数。
  • console/network 只保存投影字段；header、body、Cookie、Authorization、query secret 在落盘前脱敏。
  • artifact 上传使用相对 POSIX 路径白名单，拒绝符号链接、路径穿越和重复 real path。

Cleanup

cleanup 必须和主执行解耦。主 job 在 finally 中清理，调度器再以 always 语义启动独立 cleanup job。人工恢复入口使用原始 run id 重算同一测试身份。

  • 列出并删除所有测试创建的 key 或资源，不能只看第一页。
  • 删除测试账号或测试工件后，重新验证登录或读取失败。
  • 若 cleanup 不能证明完成，最终状态必须是 cleanup_failed。

Provider Adapters

把云厂商差异封装在 adapters：身份令牌、对象存储、Job 执行、日志 URI、服务更新、artifact content type。核心测试逻辑只依赖接口。

interface ProviderAdapter {
  getAccessToken(audience?: string): Promise<string>;
  uploadArtifact(objectName: string, bytes: Uint8Array, contentType: string): Promise<void>;
  executeJob(jobName: string, env: Record<string, string>, args: string[]): Promise<JobResult>;
  updateRuntimeImage(resourceName: string, imageUri: string): Promise<void>;
}

7. 候选固化架构：从 AI 发现到人工合并

迁移到任何项目时，都不要让 AI 直接写测试代码、JS、shell 或 selector 脚本。AI 只能提出结构化候选；运行时用 schema、origin allowlist、DSL validator、fingerprint 和 3/3 聚合决定它是否有资格进入 Draft PR。

对象含义迁移时要替换
FindingAI 发现疑似 bug；必须有证据路径和可复现步骤。severity、业务标题、目标 URL、断言。
Coverage CandidateAI 发现当前表现正常但值得长期保护的行为。业务价值、稳定预期、只读/cleanup 契约。
Fixed Case DSL可长期回归的封闭 YAML，用语义定位器和有限动作表达。fixture、origin 枚举、动作集合、断言集合。
Candidate PR Bot只消费 sanitized artifact，创建或更新 Draft PR。仓库名、目标分支、CODEOWNERS、PR 模板。

Fingerprint / Idempotency

  • fingerprint 使用规范化后的 kind + target origin/path + semantic steps + assertions 计算。
  • run id、时间、随机用户名、证据路径和截图名不参与 fingerprint。
  • 匹配 enabled fixed case：不建 PR，标记已有覆盖。
  • 匹配 open Draft PR：更新现有 PR，不新建重复 PR。
  • 匹配 closed 未合并 PR：不自动复活，要求人工判断。
  • 匹配 merged PR：标记已合并，等待下一次 regression suite 覆盖。

3/3 与 Recovery

通道3/3 规则恢复
Finding三次一致失败进入 awaiting_product_fix；修复后同一 case 三次 pass 进入 ready_for_review。产品修复后重跑候选验证；不要把 bug 复现误报成产品通过。
Coverage三次独立 pass 进入 ready_for_review。若 artifact/PR 步骤失败，用 promotion-only 从已有私有 manifest 恢复，不重跑核心业务流程。
Infra基础设施失败不计入三次业务结论。修基础设施后重跑缺失 attempt 或 promotion-only。
Cleanup任一 attempt cleanup failed 立即 blocked。先处理残留资源，再决定是否恢复候选。
人审边界：candidate-pr job 可以创建分支、更新 YAML、打开 Draft PR；它不能自动 approve、不能调用 merge endpoint、不能把 Draft PR 标成已发布事实。只有人类审核并 merge 后，case 才进入以后每次 core / regression suite。

9. 先严格 Replay 后 AI 发散的渐进路线

  1. 阶段 0：录制与 schema。只生成 record、result schema、redactor 测试和 cleanup 设计。
  2. 阶段 1：本地 replay。在开发机或 self-hosted runner 运行，无云部署，不上传长期 artifact。
  3. 阶段 2：云端 core。容器化执行，运行严格 replay，探索关闭；失败只告警。
  4. 阶段 3：有边界探索。checkpoint 后开启 5 分钟或 30 action，finding 只告警。
  5. 阶段 4：候选固化。把合格 finding / coverage candidate 转成 Draft PR，经 3/3 后等待人工合并。
  6. 阶段 5：门禁化。将高置信 replay 失败或已合并的确定性 fixed case 接入 release gate。
阶段成功标准停止条件
0record 可读，schema 固定，示例结果可校验。不能证明 cleanup 路径时停止。
1核心流程在同一环境连续通过。出现 CAPTCHA、付费或生产跳转时停止。
2云端 core 和 cleanup 均可重复。broker 或 secret 生命周期不稳定时停止。
3探索 obey budget，报告可复现。发现真实高风险 bug 时先转人工 triage。
4候选 3/3、sanitized artifact、Draft PR 和人审流程可重复。候选 cleanup_failed 或自动 merge 需求出现时停止。
5误报率和基础设施失败率可接受。cleanup_failed 永远阻断继续推广。

11. OIDC/WIF、Secret 与 OAuth

身份设计的目标是：调度器可以部署和启动 QA，但不能读取运行时 secret；执行器可以调用 broker，但不能读取 OAuth；cleanup 可以重算身份，但不能访问 AI API key。

身份最小权限不得拥有
deployer推镜像、更新 QA service/job image、execute job、读取非敏感 output。Secret payload accessor、生产 service admin。
runtime读取模型 API key 与 identity seed、调用 broker、上传 main artifacts。OAuth secret、删除 bucket 全局权限。
broker读取 OAuth secret、写 broker 日志。模型 API key、对象存储 admin、业务数据库写权限。
cleanup读取 identity seed、读写本 run cleanup manifest。模型 API key、OAuth secret、生产 admin。
candidate-pr bot写候选分支和 Draft PR；只读 sanitized candidate artifact。云厂商凭证、secret store 访问、私有 evidence 下载、merge 权限。

12. 数据与隐私

  • 每次 run 使用一次性身份，使用 HMAC(seed, run_id) 派生 username、email tag 和 password。
  • 报告只保存 run-scoped 标识，不保存完整邮箱、密码、验证码、Cookie 或完整 key。
  • 浏览器允许访问 staging origin 和只读 docs origin；生产、metadata、RFC1918、localhost、非 HTTPS 默认拒绝。
  • 截图前遮罩 input、textarea、contenteditable、验证码字段、已知 secret 和完整 alias。
  • 私有报告存储设置最短可接受生命周期，例如 7 到 14 天；不要把报告复制到 issue 或聊天。
  • 候选 PR artifact 只能包含 sanitized candidate bundle；token、OAuth、webhook、验证码、cookie、Authorization、完整邮箱和完整 API key 永不进入 artifact。
  • 模型输出必须经过 redactor 和 schema 校验；AI 叙述不能覆盖 runtime cleanup 状态。

13. 报告与仅告警模式

首版建议只告警：GitHub Summary 或发布系统只显示产品状态、replay、exploration、finding 数量、cleanup 状态、候选状态和私有报告 URI。详情留在私有对象存储。候选状态必须独立展示，不能被产品 passed 掩盖。

状态含义默认动作
passed核心回放通过、报告上传、cleanup 验证完成。绿色。
findings_detected核心通过，探索发现至少一个非 info finding。红或黄，人工 triage。
replay_failed核心流程未达 checkpoint。红，修复 replay 或产品回归。
infrastructure_failed模型、浏览器、broker、OAuth、上传、schema 或云配置失败。红，先排基础设施。
cleanup_failed无法证明测试工件已删除。最高优先级红，运行 cleanup-only 或人工处理。
候选状态含义默认动作
skipped本次未进入候选固化。只看产品主状态。
passed候选验证/PR bundle 完成，可能已有 Draft PR 待审。人工 review，不自动 merge。
cleanup_failed候选 attempt 清理失败。先处理残留资源。
infrastructure_failed候选执行或 artifact 基础设施失败。修基础设施，infra 不计入 3/3。
promotion_failed3/3 聚合未达标或候选不稳定。保留证据，人工 triage。
unknown候选步骤失败但无可信输出。fail closed。

15. Terraform / IaC 两阶段 Bootstrap

推荐把 Browser QA 放在独立 IaC root 和独立 state。第一阶段只创建基础设施和 Secret 容器；人工通过安全通道写入 secret version；第二阶段再创建引用 latest secret 的 workloads。candidate-pr bot 通常不属于云 IaC workload，它是 CI/GitHub 权限边界：只写仓库和 PR，不拿云凭证。

  1. Phase A：Artifact repository、service accounts、Secret containers、WIF、report bucket、bucket IAM。
  2. Secret versions：通过云控制台、stdin 或安全 secret pipeline 写入模型 key、identity seed、OAuth JSON。

  5. Steady state：配置保持 create_workloads=true，避免日常 plan 试图销毁 workloads。

16. 迁移步骤与分阶段 Checklist

准备阶段

  • 列出目标环境、允许 origin、禁止 origin、一次性身份策略和 cleanup API。
  • 确认不会触发真实付款、真实模型调用、生产写操作、邀请奖励或不可逆副作用。
  • 定义 result schema、manifest schema、finding 字段和状态优先级。
  • 定义 candidate schema、fingerprint 输入、3/3 规则、promotion-only 恢复路径和 Draft PR 人审规则。
  • 写 redaction 测试，覆盖邮箱、alias、密码、验证码、Cookie、Authorization、API key。

录制与去项目化

  • 录制核心流程，并把每一步改写为业务意图和成功断言。
  • 把项目名、域名、个人邮箱、绝对路径和真实资源名替换为占位符。
  • 将验证码、OAuth、第三方回调接入 broker，而不是暴露给模型。
  • 在本地或隔离 runner 中验证 replay 可达 checkpoint。

云端执行

  • 构建非 root 镜像，固定浏览器、MCP、模型 CLI 和语言运行时版本。
  • 部署 broker、main job、cleanup job，并确认 IAM 最小化。
  • 启用私有报告 bucket，设置生命周期删除和 public access prevention。
  • 部署 candidate attempt 入口，并让 main/normal 能产生 sanitized candidate bundle。
  • 先运行 core，cleanup 成功后再运行 normal；normal 必须包含完整 core。

候选固化

  • 让 AI 输出 nullable closed proposed_case，不能输出 JS、shell、任意 selector 或 secret。
  • 对每个候选运行 3 次独立 attempt，独立 evidence，infra 不计数，cleanup failed 立即 blocked。
  • 只把 sanitized artifact 交给 Draft PR bot；PR 中只放占位、证据 URI 和状态摘要。
  • 按 fingerprint upsert Draft PR；closed 未合并不自动复活，merged/open Draft 语义清楚。
  • 人审合并后，case 才能 enabled: true 进入以后 core。

推广阶段

  • 连续多次 core 通过后，把 staging pipeline trigger 接入只告警模式。
  • 探索 finding 先人工 triage，再转成确定性回归测试。
  • 建立 cleanup-only 和 promotion-only runbook，要求使用原始 run id。
  • 每次扩大触发范围前，复查成本、配额和误报率。

17. 验收标准、回滚与故障排查

验收标准

  • 核心 replay 每一步都有可验证断言，不依赖坐标。
  • AI 无法访问生产 origin、metadata、内网和未授权 docs context。
  • broker 拒绝匿名调用和越权身份，且只返回当前 run 的最小结果。
  • 报告私有、脱敏、路径白名单生效，manifest 最后上传。
  • main 失败、模型超时、workflow 取消后，cleanup-only 能用原始 run id 恢复。
  • 候选 promotion-only 能从已有 manifest 恢复 PR bundle，而不重新执行探索。
  • Finding 三次一致失败只进入 awaiting_product_fix；修复后三次 pass 才进入 ready_for_review。
  • Coverage Candidate 三次 pass 才进入 ready_for_review。
  • Draft PR bot 不自动 approve、不开 merge endpoint、不把候选直接合并。
  • Secret payload 不在 IaC state、日志、summary、截图、artifact 或提交文件中出现。

安全 Checklist

  • 调度 job 只有读仓库和云 OIDC 权限；candidate-pr job 只有写仓库和写 PR 权限。
  • candidate-pr job 没有云厂商凭证、OAuth secret、模型 API key、对象存储读取权限。
  • Sanitized artifact 不含真实 API key、OAuth token、邮箱地址、验证码、cookie、Authorization、webhook 或 signing secret。
  • 私有 evidence URI 不公开；PR 正文只引用 URI 和摘要。
  • 所有 fixed-case locator 使用 role、label、visible text 或 test id；不允许坐标、任意 CSS/XPath、JS、shell。
  • 所有生产 origin、metadata、localhost、RFC1918、非 HTTPS、支付、订阅、管理员和真实写操作默认拒绝。

回滚策略

问题回滚保留
触发噪声过大关闭自动 workflow_call 或移除 required check。保留手动 dispatch 和云资源。
镜像版本坏回滚 QA service/job image 到前一 tag。不改 secret，不删报告。
broker OAuth 失效暂停 normal，轮换 OAuth secret 后跑 core。不盲目重试。
cleanup_failed运行 cleanup-only；仍失败则人工按 run id 查私有报告。保留证据直到处理完成。
candidate-pr bot 异常保留 sanitized artifact 和私有 manifest，修权限后运行 promotion-only。不重跑探索，不手工复制 secret 到 PR。
需要撤销整套 QA先停触发，再按 IaC 审批销毁 QA 专属资源。不要用手工删除制造 drift。

故障排查

症状优先检查常见修复
manifest 缺失上传权限、bucket lifecycle、main job 是否到达报告阶段。修复对象存储权限；若 cleanup 未跑，先 cleanup-only。
验证码 pending 超时邮箱 alias、sender、subject、OAuth scope、时间窗口。修复 broker 查询条件，不让模型重发多封邮件。
replay 找不到按钮文案语言、role、URL 跳转、动画遮挡。更新语义 selector hint 和恢复策略。
探索超预算MCP wrapper phase state、action 计数、core/normal mode。fail closed，修预算状态机。
候选没有生成 PR候选是否 high confidence、proposed_case 是否非 null、fingerprint 是否重复、artifact 是否上传。按报告原因处理；PR bot 失败时运行 promotion-only。
候选状态和产品状态冲突通知渲染是否同时展示 product status 与 candidate status。候选异常必须单独显示，不能被产品 passed 掩盖。

18. 成本估算框架

先用公式估算，再用真实账单校准。不要只看模型 token；浏览器容器、对象存储、日志、NAT、OAuth/broker 请求和工程维护都要计入。

monthly_cost =
  runs_per_month * (
    build_minutes * ci_build_rate
    + main_job_minutes * container_vcpu * vcpu_rate
    + main_job_minutes * container_gib * memory_rate
    + cleanup_job_minutes * cleanup_vcpu * vcpu_rate
    + model_input_tokens * input_token_rate
    + model_output_tokens * output_token_rate
    + broker_requests * broker_request_rate
    + artifact_gib_month * storage_rate
    + log_gib * logging_rate
  )
  + fixed_private_network_cost
  + maintenance_hours * engineering_hour_rate
成本杠杆降低方法
运行次数PR 只跑轻量 contract，staging pipeline 跑 core，release candidate 跑 normal。
浏览器时间缩短 replay 恢复次数，失败时不进入探索。
模型费用固定 prompt、限制 tool action、使用 schema 输出、避免重复上下文。
日志和截图只保存关键截图、投影日志、生命周期删除。
并发每环境串行，避免争抢导致重试和清理成本。

最小验收清单

  • HTML、JSON schema、workflow YAML 和 IaC 模板均不含真实项目号、bucket、邮箱、token、secret 值或个人路径。
  • 本地 schema 测试通过；redaction 测试能拦截代表性 secret。
  • 容器 smoke 能证明非 root、浏览器可启动、MCP 可 attach，且每个 MCP server 都有精确 enabled_tools，没有 wildcard、yolo 或 danger-full-access。
  • core 模式 replay 通过并执行 cleanup。
  • normal 模式先完整执行 core，再 exploration obey budget，并只上传脱敏报告。
  • candidate 3/3 验证、sanitized artifact、promotion-only 恢复和 Draft PR bot 都有测试。
  • Draft PR 永不自动 merge，人工合并后 fixed case 才进入 regression suite。
