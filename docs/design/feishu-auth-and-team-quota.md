# 飞书登录与团队共享额度方案

**项目**：AI 接口管理平台（new-api）  
**日期**：2026-10-23

---

## 一、飞书账号登录（已上线）

### 解决了什么

每位成员通过自己的企业飞书账号登录平台，系统自动为其创建独立账号。此后每个人：

- 拥有自己的账号和独立的 API Key
- 用量记录彼此隔离，平台可按人导出用量统计
- 不再需要记忆账号密码，点击"飞书登录"一键进入

### 用户流程

1. 打开平台登录页，点击「使用飞书 / Lark 继续」
2. 跳转飞书授权页，确认授权
3. 自动回到平台，完成登录，进入个人工作台

### 管理端配置

平台管理员在后台填入飞书开放平台的应用凭据（App ID 和 App Secret），并将平台回调地址填入飞书开放平台白名单，即可开启此功能。对最终用户完全透明，无需任何额外操作。

---

## 二、团队共享额度（待实施）

### 解决了什么

飞书登录解决了"谁在用"的问题，但当前每个人登录后账号余额为零，仍需单独充值。此方案解决**统一充值、按人用量**的诉求：

- 指定一个**主账号**（如 `dengkun.test`）作为资金账号，由负责人充值
- 每位飞书成员登录后的账号作为**子账号**，自动关联至主账号
- 成员正常使用 API，消费实时从主账号余额扣除
- 主账号管理员可查看全部成员的分项用量报表

### 业务效果对比

|  | 现状 | 实施后 |
|--|------|--------|
| 充值 | 所有人用同一个余额 | 一个主账号集中充值 |
| 用量追踪 | 依赖 Key 名称人工区分 | 系统自动按人归账 |
| 权限隔离 | 无隔离 | 每人只能操作自己的 Key |
| 月度对账 | 手动整理 | 后台直接导出按人用量 |

### 资金流向说明

```
负责人充值 → dengkun.test（主账号余额）
                ↓ 实时扣费
成员 A 发起请求 → 消耗主账号余额，日志记在成员 A 名下
成员 B 发起请求 → 消耗主账号余额，日志记在成员 B 名下
```

余额由主账号统一持有，成员账号不需要单独充值，也不可自行提取。

### 可选：为个人设置用量上限

如需控制单人消费，可为每个子账号单独设置月度限额，超出后该成员请求被拒绝，不影响其他成员，主账号余额仍然保留。

---

## 三、两个方案的关系

方案一（飞书登录）已完成，可独立使用。方案二（共享额度）以方案一为前提，需在方案一上线并稳定运行后启动。两个方案可分阶段上线，互不干扰。

---

## 四、对业务的影响

- **对成员**：登录方式变为飞书一键授权，使用习惯不变，无需额外培训
- **对负责人**：充值集中管理，用量数据清晰，不再需要人工拆分账单
- **对平台**：不影响现有 API 对接逻辑，现有 Key 正常使用直至成员迁移完成
