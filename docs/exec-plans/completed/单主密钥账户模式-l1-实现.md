# 单主密钥账户模式 L1 实现

状态：COMPLETED（已完成 L1 生产人工验证；专项增强验证仍待补证据）

## 目标与非目标

- 目标：记录 L1 实现范围、产品边界和验收门槛，并记录生产人工验证结果。
- 非目标：不迁移管理员/服务账号多 Key 行为；不把未完成的跨数据库、自动化和真实供应商证据宣称为 PASS。

## 实施边界

- 普通用户仅允许一条可用主 Key；管理员和服务账号保留原有能力。
- API Key 登录与 API 额度校验分离；额度耗尽不阻止后台登录。
- 重置成功后旧 Key 立即失效并撤销旧 Session；完整新 Key 只在受控一次性响应中展示。
- 邮箱找回请求统一响应；一次性链接消费后才轮换 Key。
- 密码登录、2FA、Passkey 和既有 API Key 管理行为保持兼容。

## 当前审查结论（2026-08-13）

工作区存在后端和前端候选改动，但它们不等于已启用功能。当前至少有以下 P0/P1 缺口：

- 候选已支持管理员一次性邀请、普通用户单主 Key、API Key 登录、邮箱找回和前端一次性展示；公开 OTP 注册已被严格邀请边界阻断。
- 严格邀请覆盖普通注册、OAuth 新用户和微信新用户；已有 OAuth/微信绑定用户继续登录。
- 用户与主 Key已在候选中原子创建；注册后不自动创建后台 Session，用户保存 Key 后重新登录。该行为需作为正式产品契约确认。
- 主动轮换已加入 step-up proof；事务提交后缓存发布或 Session 撤销失败会返回一次性新 Key和非敏感 warning，并继续尝试两步，避免新 Key不可交付。
- 轮换会将新主 Key恢复为启用、永不过期，并保留原有额度；耗尽状态只影响 API 调用，不影响后台登录。
- 普通单主用户的明文 Key读取路径已收紧为创建/轮换/找回的一次性响应；静态复核未发现列表、管理员响应、邮件、URL 或日志中的完整 Key。
- 配置状态已暴露 SMTP 就绪度和旧邮件完整 Key开关冲突；尚未证明多实例验证码、SMTP 故障恢复和三种数据库兼容。
- 配置审计已补充 `.env.example` 与中文 README 的 SMTP 无密钥示例；`SMTP_FROM` 为空时回退 `SMTP_ACCOUNT`，单主模式下保存 SMTP 选项会校验有效发件地址。`single_primary_api_key_ready` 仍只表示静态配置完整，不表示供应商连通。
- 跨库静态审查：单主 Key、AuthFlow、AuthVersion 与 Session 事务均通过 GORM；`lockForUpdate` 在 MySQL/PostgreSQL 生成 `FOR UPDATE`，SQLite 跳过该语法并依赖单写者模型。未发现单主功能新增 SQLite 专属迁移。邮箱并发锁在 MySQL 依赖索引 next-key/gap lock，在 PostgreSQL 使用事务级 advisory lock，在 SQLite 以写冲突兜底；该部分仍需三库运行时验证。
- Go 与前端 gates 尚未得到 PASS，跨 SQLite/MySQL/PostgreSQL、真实 SMTP 和客户端 E2E 均未验收。
- 找回流程的未知后置异常已在控制器层收口为一次性新 Key + 非敏感告警；仍需运行时回归验证该契约，不能仅凭静态代码视为上线通过。
- 管理员用户页已增加单主模式邀请弹窗；`CreateUser` 服务端拒绝单主模式下直接创建普通用户，管理员/服务账号角色仍可创建。前端 7 个语言包已覆盖相关认证文案。
- 跨库运行时前提已记录：MySQL 邮箱锁依赖邮箱索引与隔离级别下的 gap/next-key lock；PostgreSQL advisory lock 的 hash 碰撞只造成额外串行；SQLite 依赖单写者与 busy timeout。三库并发验证仍为 NOT_RUN。
- 已补充管理员直建普通用户的回归测试用例；由于根模块依赖下载受阻，该用例当前仅作为源码级证据，不能标为运行时 PASS。
- 角色兼容边界已收紧：单主模式下管理员/Root（及未来大于等于管理员角色）保留多 Key 登录；普通用户必须唯一一条 Key；Guest 或未知低权限角色拒绝 API Key 登录。
- 前端修复了 Turnstile 参数 URL 编码、Guest 误显示单主界面、注册响应缺少完整 Key 仍跳转、轮换重复提交，以及 SMTP SSL/STARTTLS 切换的瞬时互斥问题；新增 SMTP/邀请/验证码/密码重置失败回滚测试。
- 前端受影响文件使用本地 `bun x --no-install oxfmt --check` 验证通过；仓库级 `format:check` 因 `oxfmt` 依赖安装不完整不能作为 PASS。

因此本计划早期候选阶段曾暂停；现已完成 L1 生产人工验证，未完成的专项增强验证仍不得标为 PASS。
