# 用量报表多维表格改造指引

本文档指导在飞书多维表格中创建/调整表格结构，配合后端新的用量报表快照体系使用。

## 总体说明

### 设计原则

1. **统一周期表**：日/周/月报共用一张表，通过「统计周期类型」字段区分（daily/weekly/monthly）
2. **人员字段必填**：用于多维表格自动化推送，关联到具体飞书人员
3. **后端覆盖写入**：每次同步会先删除同周期旧记录，再写入新记录，不会累积重复数据
4. **需要创建 6 张表**，不再使用旧的 9 张分散表（日/周/月 × 用户/模型/组织）；其中管理推送任务表用于承载平台日报/周报/月报消息内容，由多维表格自动化决定推送到哪里

### 配置入口

当前已在代码默认配置中内置 Base token 和 6 张表的 `table_id`，系统启动后默认启用快照生成、多维表格同步和管理推送任务写入。后台系统配置仍可覆盖这些默认值。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `stats_base_token` | `TYyybwhZKa5wzMsHGKdcGnm9nvg` | AI用量统计看板 |
| `report_table_account_id` | `tblhdpVWfwSg4U2W` | 用户/账号周期统计表 |
| `report_table_token_id` | `tblD6TWhgh35Hvzd` | Token 周期统计表 |
| `report_table_platform_id` | `tblmnSbza9Mf5tYH` | 平台总览表 |
| `report_table_model_id` | `tblYBU0ItrLbxA3t` | 模型趋势表 |
| `report_table_anomaly_id` | `tblK7YrK0n97RkEg` | 异常预警表 |
| `report_table_admin_push_id` | `tblVidLNFTD5nTyx` | 管理推送任务表 |
| `usage_report_enabled` | `true` | 启用新快照体系 |
| `usage_report_base_sync_enabled` | `true` | 启用多维表格同步 |
| `usage_report_admin_group_push_enabled` | `true` | 启用管理推送任务写入；不再由后端直发管理群 |

旧的 9 张日/周/月分散表仍保留在代码中作为兼容回退；当 `usage_report_enabled=true` 时，新链路会写入上述 6 张统一表，不再写旧表。

## 运维补跑接口

新增接口：

```http
POST /api/user/feishu/stats/report/run
```

请求示例：

```json
{
  "period_type": "daily",
  "date": "2026-07-01",
  "sync_base": true,
  "admin_push_task": true
}
```

规则：

- `daily`：`date` 表示该自然日。
- `weekly`：`date` 表示该日期所在周。
- `monthly`：`date` 表示该日期所在月。
- 不传 `date` 时，默认日报=昨天、周报=上周、月报=上月。
- 每次补跑都会先删除同周期快照，再重算；同步多维表格时也会先删除同周期旧记录，再写入新记录，因此可重复执行，不会产生重复数据。

## 迁移步骤

### 从旧表迁移到新表

1. **已通过飞书 CLI 新建上述 6 张表**
2. **已配置字段**：其中「接收人员」和「人员」字段均为飞书人员类型
3. **已将 Base token 和 6 张 table_id 写入代码默认配置**
4. **默认启用新体系**：
   - `usage_report_enabled` = true
   - `usage_report_base_sync_enabled` = true
   - `usage_report_admin_group_push_enabled` = true（写入管理推送任务表，不直发群）
5. **手动触发测试**：调用 `POST /api/user/feishu/stats/report/run` 验证快照生成、多维表格同步和管理推送任务写入
6. **配置多维表格自动化推送**：在飞书多维表格中设置"新增记录时推送给接收人员"，并为管理推送任务表配置目标群/人员
7. **旧表可保留**：旧表数据不受影响，新体系不会写入旧表；只有关闭 `usage_report_enabled` 回退旧链路时才会继续使用旧表

## 注意事项

1. **字段名必须完全匹配**：后端按中文字段名写入，多维表格字段名需与文档完全一致
2. **人员字段值格式**：后端写入的是 `open_id`，多维表格人员字段会自动匹配飞书用户
3. **覆盖式写入**：同一周期重复同步会先删除旧记录，不会产生重复数据
4. **0 用量不写入**：账号和 Token 维度只写有实际用量的数据，减少无效行
5. **组织类智能体账号**：接收人员是负责人（`agent_owner`），不是账号登录身份
