## 客户请求

```json
{
  "model": "gpt-image-2.5-4k",
  "prompt": "一座海边的小屋",
  "size": "4096x2304",
  "n": 1,
  "stream": false,
  "output_format": "png"
}
```

可用于 `/v1/images/generations`、`/v1/images/edits` 和现有图片后台任务。图生图继续使用 multipart 上传原图；中转站保留图片文件，并把上游参数转换成单张 1K PNG/base64 响应后再交给 GPU 超分。较慢的请求请使用 [图片任务接口](image-tasks.md)，POST `/v1/images/tasks` 后查询结果；同步请求仍受 Cloudflare 和客户自身超时限制。本功能不通过提前返回 HTTP 200 或空白流来掩盖超时。

仅支持单张、非流式请求及 PNG 输出；文生图使用 JSON，图生图使用 multipart。不支持透明输出或渠道参数覆盖/原样透传。普通模型行为不变。模型决定长边为 2048 或 4096，保持上游实际原图比例；size 用于指定期望比例，上游阶段缩放为长边 1024。若上游没有遵守比例，原有 output_warnings 如实报告，不拉伸或裁剪。

结果仍在 `data[0].b64_json`，尺寸字段按实际 PNG 测量。`data[0].upscale` 记录处理方法、源尺寸和目标长边。上游 usage 保留用于原有账本；成功只结算一次新模型价格。GPU 离线在调用上游前失败；生成后超分失败不自动重新生图、不冒充高清成功，按现有失败路径退回预扣。

## GPU 节点

API 服务器保存短期超分任务；节点常驻并主动通过 HTTPS 领取、下载原图、执行 Real-ESRGAN、上传结果。领取请求本身会更新可用状态，不运行额外心跳线程。节点凭据只授权这些接口，不是管理员令牌。首次初始化自动建立凭据，重启不更换；显式清空 ImageUpscaleWorkerToken 可禁用。只有站长能在渠道页下载节点配置。

在已安装 Real-ESRGAN 的 Windows 目录下建立 `relay-worker`，放入 `worker.py`、`run-worker.ps1`、`install-worker.ps1` 和下载后命名为 `config.json` 的私有配置。父目录应有 `upscale.py`、`.venv` 和 `engine`。

流水线版本还需要同目录的 `pipeline.py`、`gpu_render.py`。最多保留 3 个节点在途任务，线程间只对 GPU 引擎加锁，下载、后处理和上传可与其他任务计算重叠。每个任务使用独立持久化 JSON、原子写入结果文件；上传重试复用结果。重启和安装前必须检查 `worker-state/*.json`，不能仅检查旧版 `job.json`。

2026-09-12 单卡优化实测（既有 user-b467d84f 图片，不调用收费上游）：同一输入旧流程/新流程的本地处理耗时，2K 为 6.625/5.046 秒，4K 为 16.297/8.907 秒。逐像素 RGB 比较一致；4K 无损传输文件为 7,002,160/8,111,864 字节。新流程省掉输出 PNG 重存并使用 WebP lossless method=0，改善编码速度但增大文件，公网总耗时收益取决于链路速度。`engine_s` 包括引擎进程启动、计算及引擎 PNG 输出，不能称为纯 GPU 推理耗时。日志新增 download_s、gpu_wait_s、engine_s、encode_s、upload_ack_s、total_s；不将模拟测试或本地计时当作生产端到端吞吐证明。单卡流水线不代表支持 800 同时计算，服务器 4 个在途限制仍保留。

管理员 PowerShell 执行 `install-worker.ps1`。任务名 `HardyImageUpscaleWorker`，使用当前用户的受限 S4U 任务，开机启动、退出重启，允许单实例。运行时阻止自动休眠，显示器可关闭；不更改永久电源计划。

24 小时运行配置同时增加每 5 分钟重复触发。任务正常运行时由单实例策略忽略重复触发；进程意外退出且内置重启失效时，下一次触发会重新启动。内置重启间隔 1 分钟、最多 999 次，并启用 WakeToRun。Windows 插电状态的睡眠与休眠必须保持为“从不”；断电后能否自动开机仍由主板 BIOS 的 Restore on AC Power Loss 设置决定。

任务计划只能限制外层 PowerShell 实例；停止任务时 Windows 可能留下 Python 子进程。工作程序因此使用 Windows 文件锁保证同一安装目录只运行一个实例，安装脚本在确认没有处理中任务后会清理命令行精确指向该 worker.py 的遗留 Python 进程，再启动唯一实例。

2026-09-11 实机验收：安装后任务包含开机触发和每 5 分钟重复触发，RestartCount=999、RestartInterval=1 分钟、WakeToRun=true。清理历史遗留进程后只保留一组虚拟环境启动器/实际解释器进程；第二个 worker.py 实例因文件锁退出。17:00:57 强制结束该组进程，17:04:13 由重复触发自动恢复，恢复窗口约 196 秒。领取请求持续运行且没有额外心跳线程。插电睡眠和休眠均为 0（从不）。

网络失败时保留当前任务和结果文件，重新上传不会重新生图。结果使用无损 WebP 传输，服务器验证完整解码和准确尺寸后还原 PNG；不是有损压缩。服务器端任务最多等待 10 分钟，过期数据在节点领取时清理。进程在上游生成、计费等任意边界崩溃时，仍受原图片任务的 unknown 状态约束，不承诺分布式 exactly-once。

2026-09-12 网络恢复修复：领取请求的 socket 超时从 600 秒缩短为 15 秒，文件传输为 120 秒；网络错误后间隔 2 秒重试，并记录连接恢复。超时测试验证同一进程可恢复空闲领取，无需人工重启。节点直连公网 HTTPS，维护电脑及其 Tailscale 不参与任务链路；SSH 会话退出后服务端仍持续收到节点公网 IP 的 204 领取请求。该改动不保证互联网始终可用，也未修改服务器现有的 45 秒可用状态判断。
