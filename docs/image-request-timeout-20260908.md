## 结论与未确认项

最近的服务端真实失败是长请求超出入口等待窗口，而不能仅归因于客户重复读取响应。四组 125 秒取消与 Cloudflare 官方默认 Proxy Read Timeout 高度吻合。最可能的路径是：等待上游完整结果 → 入口超时/取消 → 后端稍后进入图片转换时发现已取消并记录 424。

客户可能先收到网关错误页，随后解析/调试读取又出现其他异常；但没有该次客户原始 HTTP 状态、Content-Type 或边缘日志，不能把客户收到 524 HTML 写成已直接观测的事实。应用日志里的 424 也不能等同于客户收到的 HTTP 状态。`Body is unusable` 的具体第二个读取者仍未从客户完整代码得到证明。

## 修复方向

- 保持渠道成功响应的 Base64 和实际尺寸要求，不通过返回空字段来掩盖失败。
- 长任务优先采用“提交任务、查询进度、读取完成结果”的方式，客户端不会持有一个超过入口超时的同步请求；需要 API Key 鉴权及防重复提交，不能直接假定当前网页登录批次接口可供外部客户替代。
- 如果客户必须保留现有同步接口，需要准备支持长请求的独立 HTTPS 接入方式，或确认 Cloudflare 套餐是否允许调高入口等待上限。此项涉及入口/网络配置，需独立验收，不能绕过现有网络保护直接修改。
- 不建议单纯加长后端图片下载超时或 Node fetch 超时；入口先断开时，这些设置不能恢复连接。不要盲目重试付费生图。
