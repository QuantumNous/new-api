## Step 1: Find a model

Open the [Model Square](https://{{API_HOST}}/pricing) and enter a model name, such as `gpt-5.6-luna`. You can filter by group, provider, and endpoint type.

In card view, click **Details**; in table view, click the model name. The request's `model` must be the full model ID, not a provider or group name.

## Step 2: Check pricing and endpoints

In the model's **Overview** tab, see **Pricing by group**. A model may have several pricing tiers, so don't rely on the base price at the top alone.

- **Input / Output**: tokens sent to the model and tokens generated by the model, respectively.
- **Cache read / write**: applies only when a request produces the corresponding cache usage.
- **Dynamic pricing**: different tiers apply based on conditions such as context length; see the tiered price table.
- **1M / 1K**: price per million / per thousand tokens, not per request.

Switch to the **API** tab, choose the format you need, and view the request example:

| Endpoint in details | Use |
|---|---|
| `openai` | OpenAI Chat Completions, used by most chat clients |
| `openai-response` | OpenAI Responses, e.g. Codex |
| `anthropic` | Anthropic Messages, e.g. Claude Code |
| `gemini` | Gemini-format requests |

Use only the endpoints listed in that model's details; the same model name does not mean every endpoint is available. The [Quickstart](/en/start/quickstart/) walks through a full `openai`-format request.

## Step 3: Match the key group

Choose a group when you [create or edit an API key](https://{{API_HOST}}/keys):

| Option | Behavior |
|---|---|
| A specific group, e.g. `ChatGPT` | Uses the models and prices supported by that group |
| `auto` | Follows the Auto group order and matches a group that supports the target model |

`auto` does not make every model available. The target model's group must be in the candidate order. With **Cross-group retry** enabled, later groups are tried only when channels in the current group fail. Switching groups may also change the price that applies.

**The Model Square lists platform models, not the models a specific key is authorized for.** Also check that the key is enabled, its group matches, and the model restrictions under Advanced settings.

With `DP_API_KEY` set, you can list the models this key can access:

```bash
curl https://{{API_HOST}}/v1/models \
  -H "Authorization: Bearer $DP_API_KEY"
```

Each `data[].id` in the response is a model ID. Confirm the API format in the model details.
