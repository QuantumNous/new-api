## 收到 429 后如何处理

| 响应信息 | 处理方式 |
|---|---|
| 包含 `Retry-After` | 按响应头指定的秒数等待后重试 |
| 响应体提示请求窗口和上限 | 降低并发，等待该窗口恢复 |
| 提示「包括失败次数」 | 先修正失败请求，避免继续占用请求配额 |

限流可能按出口 IP 或账号统计。同一出口 IP 下的其他客户端也可能影响请求额度。

## 设置重试策略

1. 仅对 `429` 和临时性 `5xx` 设置有限重试；其他 `4xx` 先修正请求。
2. 优先遵循 `Retry-After`；未提供时使用指数退避和随机抖动。
3. 设置最大重试次数及总超时时间，避免持续重试。
4. 流式响应中断后不能断点续传；重新请求可能产生额外费用。

持续触发限流时，降低并发或联系管理员调整上限。其他错误见[错误码](/api/relay/#general/guide/errors)。
