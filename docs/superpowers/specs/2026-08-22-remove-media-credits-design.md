# Flatkey 统一额度并退役媒体点数设计

## 背景与目标

Flatkey 当前在套餐、订阅权益、账户概览和官网文案中同时表达“月额度”和“媒体点数/媒体额度”。这会让用户误以为图片、视频请求使用另一套余额，也使管理端需要维护一项已经不再需要的套餐配置。

本次变更的目标是：

- 产品概念只保留一套套餐额度；图片、视频等媒体请求也从这套月额度扣费。
- 套餐额度不足时沿用现有钱包余额回退规则，不再检查或扣减媒体点数池。
- 媒体模型的独立费率配置继续保留；它仍决定请求需要多少计费额度，不是新的余额类型。
- 用户在个人资料和钱包页点击当前套餐的“月额度/限额”区域时，跳转到 `/usage-logs`。
- 管理端、用户 API、控制台、官网不再展示或配置媒体点数概念。

## 现状与约束

当前代码仍有 `media_credits_monthly`、`media_credits_total` 和 `media_credits_used` 字段，以及对应 DTO、表单、套餐卡片和官网文案。统一 `BillingSession` 已经通过订阅的 `amount_used` 和钱包余额完成普通请求的预扣、结算和退款；本次必须让媒体请求明确进入这条路径，并用回归测试证明不会写入媒体点数字段。

生产为多节点部署。正确性必须继续依赖现有数据库事务、条件更新和钱包/订阅额度账本，不能增加进程内媒体余额或锁。

## 方案

### 1. 兼容性退役

- 数据库中的旧列暂时保留，不做破坏性删列：历史快照、跨数据库升级和回滚仍可读取。
- 新建或更新套餐时，媒体点数不再出现在管理 API 的请求/响应契约中，也不再写入业务快照。
- 订阅自购、续费、升级、发票和钱包续期不再把媒体点数作为独立权益授予；旧快照中的字段只作为兼容读取数据，不能恢复成可扣费余额。
- 用户 API 和控制台响应删除媒体点数展示字段；旧客户端忽略缺失字段即可。数据库旧值不会在新的页面或接口中重新暴露。
- 不删除媒体模型费率、媒体计费倍率或模型价格配置。图片/视频实际价格仍由现有模型价格表计算。

### 2. 统一扣费

所有同步和异步媒体请求都使用 `BillingSession`：

1. 在发起上游请求前按媒体模型费率换算本次所需额度并预扣。
2. 优先从当前有效订阅的 `amount_used/amount_total` 账本扣除。
3. 订阅剩余额度不足时，由现有钱包余额路径补足或完全承担请求；沿用用户计费偏好和不足时的错误语义。
4. 上游成功后按实际用量结算差额；失败或结果不确定时沿用现有退款/保留规则。
5. 任何媒体计费流程都不得读取、增加或减少 `media_credits_used`，也不得因 `media_credits_monthly` 为零而拒绝请求。

统一会话仍负责幂等结算，订阅额度账本的条件更新保证多个 router 节点不会重复扣费。媒体请求的计费日志只记录统一额度、钱包来源和模型费率，不再记录媒体点数余额。

### 3. API、管理端与官网

- 删除套餐管理表单、校验、DTO、快照和自购/续费 payload 中的媒体点数字段。
- 删除当前订阅、套餐卡片、购买确认、个人资料摘要和使用窗口中的媒体点数区域。
- 保留并继续展示统一的月额度/限额、剩余量和使用日志入口。
- 官网套餐对比改为展示统一额度/生产使用控制，不再出现 “media credits” 或“媒体额度”。
- 保留图片、视频模型的费率配置入口和后端计算，避免把“费率”误删成“余额”。

### 4. 月额度跳转

个人资料页和钱包页当前套餐卡片中的月额度/限额区域使用应用内路由链接到 `/usage-logs`。链接不改变额度数据、刷新行为或购买按钮；键盘操作和新窗口行为遵循现有路由组件默认语义。`/usage-logs` 的既有默认 section 重定向保持不变。

## 数据迁移与回滚

本次不执行删列迁移，因此 SQLite、MySQL 和 PostgreSQL 均无需破坏性 schema 操作。部署后旧列可以继续存在，但新版本不会把它们作为业务数据源。回滚应用版本时，旧代码仍可读取历史列；回滚前后都不应把已发生的统一额度扣费反向映射为媒体点数。

如果未来确认所有历史版本和外部客户端均已退出，再另行设计删列迁移；该迁移不属于本次范围。

## 测试策略（先 RED，再 GREEN）

### 后端

- 套餐管理和自购/续费请求不再接受或返回媒体点数字段。
- 订阅摘要和当前权益只返回统一额度；旧数据库中存在媒体点数值时也不会出现在公开响应。
- 媒体请求的预扣、结算、退款测试验证只更新 `amount_used` 或钱包账本，`media_credits_used` 始终不变。
- 订阅额度不足时验证钱包回退；两者都不足时验证现有错误和无重复扣费。
- 并发媒体请求验证数据库条件更新下最多一次有效结算。

### 控制台与官网

- 套餐表单、购买对话框、钱包当前套餐和个人资料不渲染媒体点数文案或字段。
- 月额度/限额区域点击后导航到 `/usage-logs`，且其他购买/刷新交互不受影响。
- 8 个控制台 locale 同步删除媒体点数 key；官网中英文及其他本地化价格文案不再出现该概念。

### 验证命令

至少运行：

```text
go test ./controller ./model ./service
go test ./...
cd web/default && bun run test --runInBand
cd website && bun test
```

同时执行控制台类型检查、官网生产构建，并启动受影响的本地服务，通过本地页面确认额度入口可以打开 `/usage-logs`。若本地环境无法启动服务或缺少数据库配置，必须记录具体阻塞，不能以单元测试代替页面验证。

## 部署影响与验收

- Router deploy：required。统一扣费会影响 relay/计费路径以及共享订阅模型。
- Other deploy targets：`newapi-console` required（管理 API 与控制台 UI）；`newapi-web` required（官网套餐文案）；无需 Terraform 或 Cloudflare。
- 先在 staging 验证图片和视频各一条成功、失败、订阅额度不足回退钱包的低成本请求，核对统一额度账本和日志；再按正常发布流程推进。
- 完成标准：代码、API、管理端、控制台和官网不再把媒体点数当作余额；媒体费率仍可配置；媒体扣费只走统一额度/钱包；月额度入口稳定跳到 `/usage-logs`；所有目标测试和本地预览验证通过。
