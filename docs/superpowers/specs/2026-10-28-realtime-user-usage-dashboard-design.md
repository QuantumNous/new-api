# 实时用户调用看板设计

## 目标

为管理员和根管理员提供一个实时查看不同用户 API 调用情况的页面。页面位于现有 Dashboard 的 Users 分区，按 5 秒固定间隔刷新，展示最近 60 秒的调用快照和最近 10 分钟趋势。

## 用户与权限

- 仅管理员和根管理员可以访问实时用户调用接口及页面。
- 普通用户继续使用现有用户看板，不获得其他用户的调用信息。
- 后端接口必须复用现有管理员权限中间件和用户范围校验。

## 数据接口

新增 `GET /api/dashboard/realtime-users`。

请求参数：

- `window_seconds`：统计窗口，默认 60，限制在 30 到 300 秒。
- `trend_minutes`：趋势长度，默认 10，限制在 5 到 30 分钟。
- `limit`：返回用户数，默认 20，限制在 5 到 100。

返回内容：

- `summary`：活跃用户数、窗口内请求数、窗口内总 Token、当前 TPM、错误率。
- `users`：用户 ID、用户名、请求数、总 Token、输入 Token、输出 Token、TPM、错误数、最后调用时间。
- `trend`：按分钟聚合的请求数、总 Token、错误数。
- `updated_at`：服务端快照时间。

总 Token 必须使用统一的缓存计量规则：普通输入、缓存读取、缓存写入和输出 Token 合计。缓存字段从日志的结构化用量字段读取；统计接口不参与余额扣费。

## 前端布局

Users 分区增加“实时调用”视图：

1. 顶部状态条：实时状态、上次更新时间、自动刷新开关和手动刷新按钮。
2. 四个摘要卡片：活跃用户、请求数、实时 TPM、错误率。
3. 主区域左侧为用户调用表格，默认按 TPM 降序；支持按用户名搜索和按请求数、Token、错误率排序。
4. 主区域右侧为选中用户的 10 分钟趋势图；未选中时展示全体用户趋势。
5. 用户行使用活跃指示点；错误率超过阈值显示琥珀色或红色状态。
6. 空数据、加载中、权限不足和接口错误都提供明确的 i18n 文案。

## 刷新与性能

- 前端默认每 5 秒请求一次接口；页面离开或浏览器标签页隐藏时暂停刷新。
- 请求失败时保留上一份数据并显示过期状态，避免页面闪烁。
- 后端只聚合有限时间窗口，并沿用 `created_at`、`type` 等现有索引条件。
- 不在前端拉取原始日志，不把跨用户聚合逻辑放到浏览器。

## 视觉方向

采用克制的深色监控风格：深石墨背景、青绿色活跃状态、琥珀色压力提示、红色错误状态。布局使用高密度表格配合宽松的摘要卡片，突出“现在谁在调用、调用强度如何、是否异常”三个问题。保留现有 Dashboard 的主题变量、组件和响应式断点。

## 验证

- 后端测试覆盖管理员权限、窗口边界、用户聚合、缓存 Token 合计和错误率计算。
- 前端类型检查和生产构建必须通过。
- 手动验证 5 秒刷新、暂停刷新、搜索排序、空数据和接口错误状态。
