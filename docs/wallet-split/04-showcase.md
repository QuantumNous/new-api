## Showcase 1:钱包拆分与展示

**目标**:直观看到用户余额被拆成充值钱包 / 免费钱包 / 总额。

1. 管理员给 U1 手动加 100000 额度(充值钱包)。
2. 打开 U1 个人中心 → 额度区。
3. **看点**:显示三个数值——
   - 充值钱包:100000
   - 免费钱包:0
   - 总可用额度:100000
4. 断言:总额 = 充值 + 免费。

预期截图位:`docs/wallet-split/images/showcase-wallet-overview.png`

## Showcase 2:签到 → 免费钱包 + 7 天过期

**目标**:签到额度进免费钱包,有明细、有过期时间,文案含提醒。

1. U1 进入签到日历,完成验证码签到。
2. **看点 A**:成功 toast 显示"签到成功!获得 XXXX 额度。**签到额度有效期 7 天,不使用会过期**"。
3. 刷新额度区:免费钱包增加了签到额度,充值钱包不变。
4. **看点 B**:免费钱包明细列表出现一条 `来源=签到`、`过期时间=7天后`、`剩余=发放额`。
5. 断言:INV-1(总额=充值+免费)。

## Showcase 3:充值 → 本金进充值钱包 + 赠送进免费钱包

**目标**:充值拆分本金与赠送,赠送带过期。

1. 后台配置赠送规则:充 100 送 10(有效期 30 天)。
2. U1 前往充值页。
3. **看点 A**:充值页展示"充 100 送 10"提示。
4. U1 充值 $100(测试支付渠道)成功。
5. 刷新额度区:
   - **看点 B**:充值钱包 += 本金对应额度
   - **看点 C**:免费钱包 += 赠送额度,明细 `来源=充值赠送`、`过期=30天后`
6. **看点 D(缓存修复)**:充值成功后**立即**刷新即显示正确余额(不再依赖缓存 TTL)。

## Showcase 4:消费扣费顺序(三级:会过期免费 → 充值 → 不过期免费)

**目标**:演示三级扣费优先级——会过期的免费额度最先花(且即将到期优先),再花可退款的充值额度,不过期的免费额度留到最后。

1. 构造 U1:
   - 会过期免费:L1=2000(3 天到期)、L2=3000(30 天到期)
   - 充值钱包:10000
   - 不过期免费:Lperm=4000(哨兵值,不过期)
2. 用 U1 的 Token 消费约 2500(playground 或一次 chat 请求)。
3. **看点 A(即将到期优先)**:L1 剩余归 0,L2 剩余 2500;充值和 Lperm 均未动。
4. 再消费 6000:L2(剩 2500)扣光 → 充值扣 3500 → 充值钱包 6500;Lperm 仍 4000。
5. **看点 B(充值排在不过期免费之前)**:会过期免费用尽后先动**充值钱包**,**不过期免费 Lperm 保持不变**。
6. 再消费 8000:充值(剩 6500)扣光 → 从 Lperm 扣 1500 → Lperm 剩 2500。
7. **看点 C(不过期免费最后花)**:只有充值也耗尽后才动 Lperm。
8. **看点 D**:扣费日志/明细体现三级扣减来源顺序。

## Showcase 5:免费额度过期回收

**目标**:过期未用额度被回收,总额正确下降,活跃促活逻辑生效。

1. 构造 U2:免费钱包一条 L=3000,过期时间设为"已过去"(测试可直接改库或用短有效期签到 + 等待/改时钟)。
2. 触发过期回收(等后台任务一轮,或调管理接口/惰性触发:U2 发起一次消费)。
3. **看点 A**:U2 免费钱包 -= 3000,明细状态变 `已过期`。
4. **看点 B**:系统日志出现"免费额度过期回收 3000"审计记录。
5. 断言:INV-2(免费钱包 = 未过期明细剩余之和)。

## Showcase 6:兑换码增强

### 6.1 自定义 key + 免费钱包 + 过期
1. 管理员创建兑换码:自定义 key `WELCOME2026`,quota=5000,valid_days=7。
2. U1 兑换 `WELCOME2026`。
3. **看点**:免费钱包 += 5000,明细 `来源=兑换码`、`过期=7天后`。

### 6.2 一码多用(max_uses)
1. 创建兑换码 `SHARE10`,max_uses=3。
2. U1、U2、再一个用户 U3 依次兑换 → 均成功;第 4 个用户兑换 → 报"兑换次数已用尽"。
3. **看点**:兑换码管理页显示 `已用 3/3`,状态=已用完。

### 6.3 同码同人限领一次
1. `SHARE10`(max_uses=5)。
2. U1 兑换成功后**再次**兑换同码 → 报"您已兑换过该码"。

### 6.4 同标签(批次)每人限领一次
1. 批量创建带标签 `tag=promo618` 的兑换码 A、B、C(各 max_uses=100)。
2. U1 兑换 A 成功 → 再兑换 B → 报"您已兑换过该批次"。
3. U2 兑换 B 成功(不同用户不受限)。

### 6.5 标签删除清理限领记录
1. 删除 `promo618` 批次兑换码。
2. 用相同 tag 重新生成新码 D。
3. U1 兑换 D → **成功**(旧限领记录已随标签删除清理)。

3. 构造"扣费后免费明细已过期"场景再退款:
4. **看点 B**:退款转入充值钱包(不复活已死明细)。
