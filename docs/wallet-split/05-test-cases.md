# 双钱包拆分 — 测试用例

## A. 钱包拆分与不变式

### TC-A01 存量迁移
| 项 | 内容 |
|----|------|
| 场景 | 上线迁移,存量用户仅 quota 有值 |
| 前置 | 用户 quota=100000,无 free_quota_ledger |
| 操作 | 执行 AutoMigrate |
| 预期 | free_quota=0,quota=100000,总额=100000 不变;INV-1 成立 |

### TC-A02 总额一致性
| 项 | 内容 |
|----|------|
| 场景 | 任意入账后总额校验 |
| 前置 | quota=50000 |
| 操作 | AddFreeQuota 30000(7天后过期) |
| 预期 | quota=50000, free_quota=30000, 总额=80000;INV-1/INV-2 成立 |

## B. 扣费顺序(三级:会过期免费 → 充值 → 不过期免费)

### TC-B01 优先扣会过期的免费额度
| 项 | 内容 |
|----|------|
| 场景 | 消费时存在会过期的免费额度 |
| 前置 | quota=10000, 免费明细 L1=5000(10天到期);free=5000 |
| 操作 | 消费 3000 |
| 预期 | L1 remaining=2000;free=2000;quota=10000 不变;fromFree=3000, fromRecharge=0 |

### TC-B02 会过期额度内即将到期优先
| 项 | 内容 |
|----|------|
| 场景 | 多条会过期明细不同过期时间 |
| 前置 | L1=2000(3天到期), L2=3000(10天到期);free=5000 |
| 操作 | 消费 2500 |
| 预期 | L1 remaining=0(exhausted), L2 remaining=2500;严格先扣 L1 |

### TC-B03 会过期免费不足→扣充值(不动不过期免费)
| 项 | 内容 |
|----|------|
| 场景 | 三级验证:充值排在不过期免费之前 |
| 前置 | 会过期免费 Lexp=2000(5天到期);充值 quota=10000;不过期免费 Lperm=4000(哨兵) |
| 操作 | 消费 5000 |
| 预期 | Lexp 扣光 2000 → 充值扣 3000(quota=7000)→ **Lperm 不动**(仍 4000);fromFree=2000, fromRecharge=3000 |

### TC-B04 充值也不足→最后扣不过期免费
| 项 | 内容 |
|----|------|
| 场景 | 扣到第三级 |
| 前置 | 会过期免费 Lexp=2000;充值 quota=1000;不过期免费 Lperm=5000 |
| 操作 | 消费 6000 |
| 预期 | Lexp 2000 + 充值 1000 + Lperm 3000;Lperm remaining=2000;quota=0;fromFree=5000, fromRecharge=1000 |

### TC-B05 纯充值(无免费)
| 项 | 内容 |
|----|------|
| 前置 | quota=10000, 无免费明细 |
| 操作 | 消费 4000 |
| 预期 | quota=6000;fromFree=0, fromRecharge=4000 |

### TC-B06 总额不足拒绝(原子)
| 项 | 内容 |
|----|------|
| 前置 | 会过期免费 1000 + 充值 500 + 不过期免费 500(合计 2000) |
| 操作 | 消费 3000 |
| 预期 | 返回错误,三处余额均不变,无部分扣减 |

### TC-B07 只有不过期免费额度
| 项 | 内容 |
|----|------|
| 场景 | 无会过期免费、无充值,仅不过期免费 |
| 前置 | quota=0, 不过期免费 Lperm=5000(哨兵),无会过期明细 |
| 操作 | 消费 3000 |
| 预期 | Lperm remaining=2000;free=2000;fromFree=3000 |

## C. 免费额度过期回收

### TC-C01 后台任务回收过期未用
| 项 | 内容 |
|----|------|
| 场景 | 定时任务扫描过期 |
| 前置 | 免费明细 remaining=3000,expired_time=昨天 |
| 操作 | 运行 StartFreeQuotaExpireTask 一轮 |
| 预期 | 明细 status=expired,free_quota-=3000,写系统日志;INV-2 成立 |

### TC-C02 扣费时惰性回收
| 项 | 内容 |
|----|------|
| 场景 | 消费前触发惰性清理 |
| 前置 | L1=2000(已过期), L2=3000(未过期);free=5000(含过期未回收) |
| 操作 | 消费 1000 |
| 预期 | 先回收 L1(free-=2000),再从 L2 扣 1000;L2 remaining=2000;free=2000 |

### TC-C03 已耗尽明细不重复回收
| 项 | 内容 |
|----|------|
| 场景 | remaining=0 的过期明细 |
| 前置 | L1 remaining=0, status=exhausted, 已过期 |
| 操作 | 运行回收任务 |
| 预期 | free_quota 不变(不重复扣);状态可置 expired 但不减余额 |

## E. 充值赠送

### TC-E01 本金进充值 + 赠送进免费

### TC-E04 充值缓存一致性

| 预期 | Redis 值 == DB 值,无需等 TTL |

### TC-F03 valid_days=0 进充值钱包

|----|------|
| 前置 | 兑换码 valid_days=0 |
| 操作 | 兑换 |
| 预期 | 进充值钱包(现状行为),不产生免费明细 |

### TC-F04 max_uses 多次核销

### TC-F06 同标签同人限领一次

### TC-F07 不同用户互不影响
| 前置 | 同 TC-F06 |
| 操作 | 用户1 兑 A,用户2 兑 B |
| 预期 | 均成功 |

### TC-F08 标签删除清理限领记录
| 项 | 内容 |
|----|------|
| 场景 | 删除批次 |

## H. 并发与兼容

### TC-H01 并发扣费无双花

| 操作 | 分别在 Batch 开/关下跑 TC-B01~B07 |

| 操作 | Redis 启用/禁用下跑扣费 |

| 预期 | 行为与结果一致 |
