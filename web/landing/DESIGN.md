## 设计定位

HelloCoder 的视觉系统服务于“一个接口连接多个模型与客户端”这一核心概念。页面应像一件可靠的开发者工具：结构一眼可读、信息密度适中、技术感来自真实的关系和状态，而不是装饰性特效。

当前 Hero 是设计系统的基准实现，源文件包括：

- [`components/hero/hero.tsx`](components/hero/hero.tsx)：页面栅格、主标题和响应式框架。
- [`components/hero/animated-beam.tsx`](components/hero/animated-beam.tsx)：模型、平台与 HelloCoder 的关系可视化。
- [`components/hero/hero-cards.tsx`](components/hero/hero-cards.tsx)：高强调行动卡片及其交互动效。

## 核心原则

1. **信息先于装饰。** 每个大色块、图标和动效都必须表达入口、连接或状态。
2. **中性画布承载高饱和重点。** 大部分页面使用白色和柔和灰色，蓝色与青绿色只用于品牌关键词、连接光束和关键行动。
3. **大标题负责定位，小组件负责证明。** 标题解释价值，关系图和节点展示产品如何工作。
4. **圆润但不轻浮。** 大容器使用 28–32px 圆角；功能节点使用 16px 或胶囊形，形成明确层级。
5. **动效表达连续性。** 模型名变换、光束流动和卡片悬浮都应表达“连接与切换”，避免无意义漂浮。

## 色彩系统

### 中性色

- **Canvas — `oklch(0.97 0 0)`**：桌面页面背景，负责分离白色内容面板。
- **Surface — `oklch(1 0 0)`**：主内容面板、节点和卡片内部元素。
- **Surface Soft — `oklch(0.985 0 0)`**：关系图容器及低强调区块。
- **Ink — `oklch(0.145 0 0)`**：标题和主要正文。
- **Ink Muted — `oklch(0.556 0 0)`**：说明文字，不用于关键信息。
- **Line — `rgb(0 0 0 / 6%)`**：大容器边界。节点可提高到 `10%`，但仍保持轻量。

### 品牌与行动色

- **Blue — `oklch(54.6% 0.245 262.881)`**：主品牌色、模型动态词和一级行动卡。
- **Teal — `oklch(77.7% 0.152 181.912)`**：次级行动卡，与蓝色形成冷色互补。
- **Beam Blue / Cyan — `#2563EB → #22D3EE`**：只用于连接光束和极少量动态反馈。

高饱和色应以完整、纯色表面出现。不要为普通内容区增加渐变背景；渐变只允许出现在光束、进度或短暂状态中。

## 排版系统

### 字体

界面以 Inter 为主，Geist 和系统无衬线字体作为回退。代码、API Key 和命令行内容使用 Geist Mono。中文与英文混排时，在中文和英文品牌名、模型名之间保留空格，例如“使用 HelloCoder”“访问 HelloCoder 中转站”。

### 层级

- **Hero Display**：`clamp(32px, 3.5vw, 64px)`、700、`1.08` 行高、`-0.04em` 字距。
- **Action Card Title**：移动端约 22–26px；桌面 `clamp(28px, 2.2vw, 44px)`、700。
- **Lead**：`clamp(18px, 1.4vw, 22px)`、500、宽松行高，使用 muted 色。
- **Body**：16px / 1.5，承担说明和功能内容。
- **Caption / Node Label**：8–12px、600，只用于紧凑关系图；常规正文不得使用这一尺寸。

标题最多承担两个语义层级：稳定的黑色主句与一个蓝色动态关键词。不要在同一标题中使用更多颜色、描边或阴影。

## 栅格与响应式

### 桌面（`lg` 及以上）

- 最大内容宽度为 `1600px`，外边距自动居中。
- 外层使用双栏网格：`1.75fr / 0.75fr`，右栏最小宽度 `320px`。
- 页面内边距和栏间距均为 `20px`，形成稳定的方形节奏。
- Hero 高度为 `min(800px, 100svh)`，最小高度 `704px`；在常见笔记本视口中不制造无意义滚动。
- 左侧面板由标题区与关系图区构成，约为 `0.85 / 1.15` 的纵向比例。
- 右侧行动卡纵向排列，默认采用 `60% / 40%` 比例。

### 移动端

- 外层使用单栏，`12px` 内边距和 `12px` 间距。
- 主内容最小高度约 `544px`，标题与关系图保持完整但减少空白。
- 两张行动卡改为等宽双列，高度 `176px`；内容必须在 320px 宽度下无横向滚动。
- 页面背景切换为白色，移除主面板边框，让有限空间更轻、更连续。
- 动态模型词允许换到独立一行，不压缩字号来强行保持单行。

## 形状、边界与层次

- **主面板 / 行动卡**：32px 圆角。
- **关系图容器**：28px 圆角，`6%` 黑色边框。
- **中心连接器**：16px 圆角，以浅蓝底、蓝色文字和轻微蓝色阴影突出。
- **模型与客户端节点**：胶囊形、白底、`10%` 黑色边框。

整体以平面层次为主。阴影只用于小型悬浮节点和中心连接器，且必须大范围、低不透明度；大卡片和大内容区不使用常规投影。

## 组件语言

### Hero 标题

- 第一行说明品牌或动作，第二行解释核心价值。
- 动态模型名称使用品牌蓝，并与主句保持相同字号和基线。
- 说明文字与标题保持 16–20px 的视觉间隔，语句短、直接，不堆叠功能点。

### 连接关系图

- 使用“三列结构”：输入模型 / HelloCoder / 输出客户端。
- 左右节点数量和垂直节奏尽量对称，中心节点始终位于视觉中心。
- 静态路径使用浅灰蓝，动态光束使用蓝到青的短渐变。
- 节点图标承担品牌识别，文字保持技术命名，不添加说明段落。
- 在极窄屏幕中优先减少节点水平内边距，不能隐藏或裁切关键名称。

### 行动卡片

- 每张卡只表达一个动作：一个图标、一个标题、一句说明和一个方向箭头。
- 图标置于左上，箭头置于右上，文字锚定左下，形成对角线视觉动势。
- 卡片使用纯色背景和白色文字；说明文字使用 `80%` 白色。
- 桌面悬浮时，标题可通过模糊过渡放大至约 `1.6×`；箭头采用“旧箭头离场、新箭头入场”的连续动作。
- 移动端不依赖 hover 才能展示任何关键信息。
- 键盘焦点使用清晰的白色内描边，交互状态不得只依赖颜色区分。

### 价格信息卡排版

价格信息卡的具体内容可以随付费方案调整，但以下文字层级与排版关系应作为可复用设计模式保留：

- **卡片标题**：移动端 `18–20px`，桌面 `24px`，700 字重，行高约 `1.08–1.15`，字距为 `-0.025em` 至 `-0.035em`；使用 Ink 色。
- **说明文字**：移动端 `14px`，宽屏 `16px`，500 字重、宽松行高；使用 Ink Muted，与标题保持 `12–16px` 间距。
- **信息标签**：`14–16px`、600 字重、Ink Muted，用于“支付金额”“倍率”等真实字段，不用作装饰性眉标。
- **主要数值**：`30–36px`、700 字重、紧行高、`-0.04em` 字距；用于需要优先读取的金额或额度。
- **行内字段名**：`14–16px`、600 字重、Neutral 600；与数值成对出现时保持紧凑、稳定对齐。
- **行内强调值**：`20–24px`、700 字重、`-0.025em` 字距；品牌蓝只用于倍率、到账额度等关键结果。

排版优先使用“标题与说明在上、核心数据在下”的纵向结构；多个价格并列时使用等宽网格，并让字段名与对应数值形成明确的一对一关系。不要通过装饰图标、徽标、无意义小字或额外背景制造层级。即使页面暂时不展示金额卡，也应复用上述字号、字重、颜色和间距关系组织新的定价信息。

## 动效规范

- 快速离场：约 `160–280ms`，使用标准加速曲线。
- 柔和入场：约 `280–360ms`，优先使用 `[0.16, 1, 0.3, 1]`。
- 光束单次流动约 `3–3.5s`，相邻路径错开约 `120ms`，保持连续而非同步闪烁。
- 模型名使用模糊融合切换，避免逐字打字造成页面抖动。
- 所有新增装饰性动效必须尊重 `prefers-reduced-motion`；减弱动效后仍需保持完整信息层级。

## 后续页面延展

Hero 下方的新区域应延续同一套规则：白色或柔和灰色大画布、32px 大容器圆角、清晰黑色标题和有限的蓝/青强调。建议每个视口最多出现一到两个高饱和表面，其余内容通过边框、留白和排版建立层次。

适合复用的模式包括：

- 数据带：无阴影、细分隔线、强数字与短标签。
- Bento 功能网格：白色卡片、轻边框，只有主卡可使用浅蓝底。
- 三步接入流程：胶囊步骤编号、灰色连接线、蓝色当前状态。
- 价格对比：中性表格为主，只高亮推荐列和主要 CTA。
- FAQ：简洁分隔线，不使用多层卡片嵌套。

## Do / Don't

### Do

- 使用大字号、紧行高和明确的左对齐建立开发者产品感。
- 让品牌色绑定明确语义：蓝色代表主要连接或行动，青绿色代表辅助行动。
- 用 12 / 16 / 20 / 24 / 28 / 32px 构建可感知的间距节奏。
- 在 320px、390px、1024px 和 1440px 视口验证核心页面。
- 保持语义化结构、键盘焦点和可理解的无障碍名称。

### Don't

- 不要用大面积装饰渐变、玻璃拟态或高强度发光。
- 不要给所有容器都添加阴影；优先使用留白和轻边框。
- 不要在同一视口堆叠多个高饱和色块。
- 不要使用与功能无关的插画、装饰图标或漂浮粒子。
- 不要让正文小于 14px；8–12px 仅限空间受控的关系图节点。
- 不要依赖 hover 才能理解组件，也不要让动效改变页面布局。
- 不要把中文和英文品牌名直接粘连，也不要随意改变模型官方命名和大小写。
